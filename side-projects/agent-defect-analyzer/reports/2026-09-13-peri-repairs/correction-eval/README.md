# 用户纠正后的任务目标校准

对应 `PERI-20260913-CORRECTION-SCENARIO`；issue 基线保留在 commit `73df17f7`。现行规则由 `peri-acp/prompts/sections/03_doing_tasks.md` 与内置 `ultra-task/SKILL.md` 持有。

规则要求在用户纠正后重新关联触发/输入、预期行为和实际结果，用可得证据决定下一步检查；机制质疑本身不足以授权架构替换。用户明确更换目标时更新计划和受影响的子任务，保留其继续适用的约束。必要区别无法从现有证据确定时才提问。运行时判断可读取日志或复现，不再把用户当作一切运行时事实的唯一来源。

## 验证与结论

- 最终代码上的 `cargo test -p peri-acp --lib prompt::tests`：105 通过，0 失败；覆盖 prompt 组装、feature gates、冻结及字节一致性相关路径。
- `cargo test -p peri-middlewares --lib test_ultra_task_skill_registered_and_discoverable`：1 通过，证明内置 skill 仍由 Peri parser 正常加载并可发现。
- 独立 code review 没有发现本次 prompt/skill 改动的功能或授权阻断。
- 按 `protocol.md` 冻结 8 个合成场景，两版各独立运行两次，顺序为 A1、B1、B2、A2。版本和输入 SHA-256、原始输出、盲化顺序、评审及协调者复核分别保存，32 份决策只有 8 个唯一场景。

两版在目标、证据使用、下一步方向及授权四维均得到通过。两个明确改变目标的反例都被保留，没有被压回旧修复；明确事实场景没有重复询问平台、审批或旧 CI 是否属于当前改动。

澄清维度有两项分歧：原评审把索取 UI 选择记录、额外运行日志判为不必要。协调者在揭示版本前复核认为，这些材料可能帮助区分取消入口或到期行为，但当前合成记录不足以证明其必要性或无效性，因此保留为 unknown。揭示版本后，两项分歧分别出现在候选一次和基线一次。原始 fail 标签没有被覆盖。

**本轮没有证明候选比基线更好。** 两版表现接近，场景纠正较明确，可能存在天花板效应；下一步决策文本也不证明实际执行了测试、修复或及时继续了独立工作。没有留出集、真实 Peri provider 输入重放、生产对照或统计功效保证。规则采纳的依据是明确任务边界且未观测到硬目标/授权回归，生产收益仍需真实任务验收。

## 材料与适用范围

`summary.json` 按每次运行与每个维度保留原评审/协调标签。`coordinator-audit.json` 是揭示版本前的事实检查，`coordinator-adjudication.json` 保存两个澄清分歧。`outputs-*.json` 是决策原文，不是任务完成记录；不能把它们计入生产成功率。

Peri 的 system prefix 遵守会话冻结契约；本次没有重写已有会话的冻结内容。新规则在重新构建后的新会话中生效。
