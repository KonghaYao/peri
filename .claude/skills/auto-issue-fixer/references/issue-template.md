# Issue 文档模板

所有类型 issue 共享的头部和尾部，中间按类型追加不同段落。

## 通用头部

```markdown
# [简洁描述现象，从用户视角出发]

**状态**：Open
**优先级**：[高/中/低]
**创建日期**：YYYY-MM-DD

## 问题描述

[2-5 句话概括。包含：什么场景下、看到了什么、期望看到什么]
```

## 按类型追加段落

### Bug/异常行为类

```markdown
## 症状详情

[具体表现：表格、步骤序列、截图描述（文字形式）]

## 复现条件

- **复现频率**：[必现/偶发/仅在特定条件下]
- **触发步骤**：
  1. ...
  2. ...
- **环境**：[模型、OS、配置等]

## 涉及文件

- `path/to/file.rs` —— [此文件在问题中的角色]
```

### 重构/技术债类

```markdown
## 现状

[当前代码的问题。可选：行数/文件大小等可直接观察的数据]

## 期望改进方向

[用户希望达到的效果，用用户自己的话描述]

## 涉及文件

- `path/to/file.rs`（N 行）—— [说明]
```

### 性能类

```markdown
## 性能数据

[用户提供的性能指标、测量数据]

## 出现场景

[在什么规模/负载/条件下出现]

## 涉及文件

- `path/to/file.rs` —— [此文件在问题中的角色]
```

### 安全类

```markdown
## 风险描述

[用户描述的安全风险和攻击面]

## 影响范围

[受影响的数据、用户、系统]

## 涉及文件

- `path/to/file.rs` —— [此文件在问题中的角色]
```

### 文档类

```markdown
## 现状

[当前文档的问题——缺失/过时/不准确]

## 期望补充内容

[用户希望看到什么信息]

## 涉及文件

- `path/to/doc.md` —— [说明]
```

## 通用尾部（所有类型必需）

```markdown
## 状态变更记录

| 日期 | 从 | 到 | 操作人 | 说明 |
|------|-----|-----|--------|------|
| YYYY-MM-DD | — | Open | agent | 创建 |

## 修复记录

（由 auto-issue-fixer 修复阶段追加，创建时留空）
```

## 修复记录格式（修复阶段追加）

```markdown
### 修复 #N（YYYY-MM-DD）

- **操作人**：[agent / 用户名]
- **用户原意**：[用户希望达到什么效果，用用户自己的话概括]
- **修复内容**：[改了什么文件，做了什么改动]
- **涉及 commit**：[commit hash，如有]
- **验证状态**：待验证 / 已验证 / 验证失败
```

多次修复独立成段，不删除旧记录。

## 文件命名

- 路径：`spec/issues/YYYY-MM-DD-<slug>.md`
- slug：从标题生成，kebab-case，描述**现象**（不是根因）
- 示例：`spec/issues/2026-07-20-scroll-cpu-high-on-raspberry-pi.md`
