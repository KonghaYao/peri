# V5 长会话内存治理

状态：已批准目标；部分预算/释放机制已存在，长时证据未闭环。
需求权威：[Issue #447](https://github.com/KonghaYao/peri/issues/447)。本文只承接仓库内目标路由与缺口，不新建资源 owner 表。

## 范围

现有 Agent、Middleware、TUI 的长寿命资源须具有可追踪所有者、作用域、容量预算、背压或淘汰边界和取消/释放责任。持久历史不等于内存驻留；未可靠交接的结果不可因展示淘汰而丢失。具体能力所有权仍归 [Middleware 契约](../../docs/design/middleware-system.md)，不是独立内存控制面。

已有入口包括 [Agent memory probe](../../peri-agent/src/session/memory_probe.rs)、[transcript memory probe](../../peri-agent/src/session/transcript_memory_probe_test.rs) 及 [Compact 设计](../../docs/design/micro-compact.md)；这些入口不证明全局预算已经实现。

## 验收缺口

- 对 session、子任务、MCP 连接/订阅、队列、TUI 历史与工具输出逐项核对实际容量和释放时点。
- 固定代表性负载记录 RSS/heap（可用时）、活动对象、队列和任务数，区别 allocator 高水位与持续累积。
- 保留原始日志、平台、版本、预热/采样/容差及通过阈值；没有实测不得写已验证有界。
- 不改变无关运行行为或数据库结构；E2E 场景由 peri-e2e #10 管理，Rivet 真实连续性由 #448 承担。
