## 方法正确性：PASS

双方使用同一生成器、同一 12k 历史和分片工作量，都经过真实 demo adapter 的 base64 编码、JSON body 字节统计、base64 解码及 Yjs apply，并在接收副本上运行 `SessionViewStore`。每 64 分片显式 flush 并让出一个微任务，控制视图发布节奏；该设计确实覆盖了“长历史＋长输出＋接收视图”组合，补上前面单独场景的缺口。

257 次发布的断言来自 256 个分片批次加最后完成状态；script 同时断言每次首工具非空，结束后再校验整个历史与全文，因此不能靠移除历史或少发布来通过性能场景。基线的 43/44/44 次发布仅表示截断前完成的批次。

计时区间从首个流分片之前开始，覆盖 completed、最终 flush、等待 close、接收 apply 和视图微任务。**327.620 ms 中位数仅属于这一流式区间**：12k 历史构建、初始快照、初始与最终全文验证均不在其中。整个场景的预算仍覆盖上述阶段，全场景耗时中位数为 **939.622 ms**。报告已正确分别展示两种计时。

初始快照 JSON 字节使用 base64 长度加空载荷 envelope 长度计算，base64 内容无需 JSON 转义，因此该算法给出相同 body 字节数，同时避免仅为统计分配另一份大型 JSON 字符串。双方仍未模拟真实 socket、JSON.parse、HTTP/SSE headers 或浏览器绘制，不能将该结果称为真实浏览器端到端性能。

## 调度与可复现性：PASS，限定静态证据范围

已发现并披露的早先重叠组存于 [baseline-combined-overlap](raw/baseline-combined-overlap/summary.json)，其 [无效标记](raw/baseline-combined-overlap/INVALID_FOR_COMPARISON.json) 明确说明与 SDK build/test 并发。正式报告中的数据来自重跑目录，与无效组不同；没有引用重叠组的数字计算结论。

正式基线的记录窗口约为 UTC 17:02:51.692–17:02:59.810，候选约为 17:03:33.473–17:03:36.345，彼此分离；各组 runner 都等待前一子进程退出后再启动下一个。第三轮原场景、SSE 补采及两组合正式样本共 21 个记录时间区间均无交叠。provenance 另记录正式补采与其他 CPU 工作无重叠；这是执行协调记录，静态 JSON 无法提供机器上所有无关进程的完整活动证明。

两组 provenance 指向同一个八文件 harness 归档，归档 SHA-256 和所有脚本指纹均匹配；最终候选源码来自第三轮已验证归档，基线由指定 Git 提交重建。两组同一生成器、锁文件和 Bun/Yjs 版本可核对，既有原始文件没有被重跑覆盖。

## 结论合理性与报告质量：PASS

独立重算候选三次流式耗时为 **327.620 / 316.346 / 339.749 ms**，均值 327.905 ms、中位数 327.620 ms、样本标准差 11.704 ms；apply 均值 10.436 ms、中位数 10.325 ms、标准差 0.332 ms，均与报告一致。全场景耗时为 939.622 / 912.106 / 945.164 ms。

候选全场景峰值 RSS 为 **1,849.500 / 1,851.188 / 1,763.813 MiB**，均在预算内。该峰值包含完整载荷、运行时、两份文档、base64 缓冲、缓存视图与全文校验；不能解读成单个常驻文档占用。基线测量被预算截断，因而不能声称候选相对“完整基线峰值”节约某个百分比，也不能保证任意 2 GiB 容器或多客户端场景都能复现。

可直接比较的完整阶段是初始快照：基线 **115,968,355 V1 bytes / 154,624,565 JSON bytes**，候选 **23,059,316 V2 bytes / 30,745,880 JSON bytes**。这是尚未结束的历史 turn，不能与已完成 turn 的单独 tools 快照混用；候选完整结果仍保留在 owner 的外置载荷中，快照缩小不代表全文消失或总存储等比例下降。

报告对基线截断、重叠排除、冷热计数、结束边界和近预算占用的说明完整。原计划中的完整组合被实际执行并保留失败数据；未凭候选完成而伪造基线完整时间，也未以资源超限改低工作量后宣称完成原目标。

## 后续结论的使用范围

最终综合结论应保留三点：组合候选在规定本地预算内完成；基线仅完成约 2.7 MiB 后截断，无法给全程比值；纯流式实际 adapter 约与基线持平，其显著收益主要在帧数。恢复、慢消费者、重复/乱序、取消、销毁、buffer 转移与浏览器实际运行由各自契约测试和独立验证提供证据，不由本吞吐实验代替。
