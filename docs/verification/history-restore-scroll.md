# 长会话恢复与向上分页验收

基线为 `4b78c0b26dcda53109db0316b49d31b68b846150`。Linux x86_64 上使用真实 TUI 与内嵌 ACP，终端尺寸 120×40。数据为合成会话，可以不接外部模型。macOS 用户截图中的 363 MB 是现象记录。

| 入口 | 验收方式 |
| --- | --- |
| `/history` | 菜单按 Enter 进入含 5,000 轮中文对话与 Shell 结果的会话；共 20,000 行、118,116,670 字节。确认最后答复出现时读取同一 PID 的 RSS，再读第 25 秒。对照组使用同一数据库，只保留末 50 行为执行有效消息。 |
| 冷开、热开与关闭 | 按请求划分 SQLx 日志，核对无界正文查询次数；在全有效及末 50 行有效两种条件下各两次重开，比较第一页 50 项的完整 JSON 摘要。 |
| 上翻 Markdown | 初始窗口在末尾，连续回看 19 页，每页 50 条。记录每次并页扫描/重绘数量和同步布局耗时。另一轮每 50 ms 发送 Ctrl+Home，以屏幕上实际出现的旧消息编号计时。纯滚轮独立运行。 |
| 折叠工具结果 | 在新窗口票据下首次翻到 1、8、32 MiB 的普通工具输出，各取五次。核对描述符、隐藏条目和详情请求。 |
| 继续与关闭 | 使用本地回环模型捕获第一次请求，核对旧用户消息、工具调用 ID 及结果的顺序，排除已归档内容。分别验证新输入、空“继续”、待执行会话自主续跑，以及首次读取正文期间的 Stop/close 和代次替换。 |
| 两种存储 | SQLite 检查锚点两侧的内容、顺序及索引步数；PostgreSQL 使用真实服务检查初始游标、继承区及有效消息标志。 |

中文菜单样本 SHA-256 为 `9846163510096af61a86fe65de63cf8d64cf40659238a67da3ee7b85e92ede22`。在 20 万行 SQLite 深页对照中，保留同一结果集的 51 个候选行从 1,399,203 条虚拟机指令降到 660 条，另验证了 64 组游标边界。默认浏览仅装载显示页，并在旧分页协商时检查获得首个可见锚点所需的候选行。恢复后首次实际执行仍按原契约加载有效上下文。子会话执行仍需读取继承区。

相应的回归用例位于 `peri-acp` 的 `history_page_window_test`、`peri-resources` 的 SQLite 与 remote 会话测试、`peri-tui` 的 `message_area` 和 `history_window`。发布交接包另附相同编译 profile 的二进制摘要、原始指标及合成数据生成脚本。
