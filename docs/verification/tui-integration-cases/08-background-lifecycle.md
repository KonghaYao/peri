# 后台任务生命周期

按 [总目录](README.md) 的编号执行。除特别说明外，等待期间不再提交用户输入，以验证任务自身的续跑责任。

1. **P0-38 后台投递暂时失败后自行结算**（[issue](../../../spec/issues/2026-10-09-subagent-callback-chain-audit.md)）
   1. 启动后台子任务，让首次父队列接纳暂时失败，随后恢复接纳。
   2. 不发新 prompt、不退出进程，等待原任务结算和父任务回应。
   3. 核对稳定 delivery ID 只投递一次；失败期间保留结果，不重跑子工具，恢复后自动完成。
2. **P0-39 预算边界仍消费后台结果**（[issue](../../../spec/issues/2026-10-08-background-result-consumed-before-budget-check.md)）
   1. 让父任务接近语义迭代或推理预算边界，同时完成后台子任务。
   2. 等待父 loop 的退出复查或自动续跑，不再发送用户输入。
   3. 核对后台结果只进入一次后续模型请求，并有父回复；预算边界不应吞掉投递资格。
3. **P0-40 取消后台子任务仍交付终态**（[issue](../../../spec/issues/2026-10-09-subagent-callback-chain-audit.md)）
   1. 启动后台 Agent，确认父会话能看到运行条目后取消该子任务。
   2. 等待 child 退出、父任务收到取消结果，再查看任务详情。
   3. 核对原 task ID 只结算一次，卡片不永久运行；父任务不因取消回调丢失而等待新输入。

## P1 补充场景

1. **P1-03 执行失败后新错误通知仍能激活**（[issue](../../../spec/issues/2026-10-08-async-error-notification-activation.md)）
   1. 让父模型请求失败，再让后台任务产生新的 Required 错误通知。
   2. 不发用户输入，观察父会话是否因新通知重新进入处理。
   3. 核对新错误被消费一次；旧失败请求不自旋重试，主动 Stop 后不自动激活。
