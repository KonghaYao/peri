# Peri 工具错误自动纠正机制——Agent 调工具失败后框架如何帮它修复

> **[Peri Code](https://github.com/konghayao/peri)** — 用 Rust 写的开源 Coding Agent，兼容 Claude Code 生态。<https://github.com/KonghaYao/peri>

有一次 Peri 在执行消息管线重构时，编辑工具连续 3 次在同一个文件上报 old_string 未找到。如果不加干预，Agent 会陷入重试-失败循环——每次都用同一个错误的 old_string 重新提交，相当于用头撞同一堵墙。Peri 在框架层注入了一条**纠正消息**，告诉 Agent 错误原因是缩进字符不匹配，建议用 Read 工具重新读取目标文件获取精确内容。Agent 读文件后修正了 old_string，第 4 次编辑成功。

这个场景背后是 Peri 的**工具错误自动纠正系统**——当 Agent 的工具调用失败时，框架不直接把原始错误信息扔回去，而是分析失败的根因后注入带有修复建议的纠正消息。这个机制让 Agent 的工具调用成功率从 74% 提升到 93%，机制分为三个环节——错误分类、建议生成、注入时机。

## 错误分类器将工具失败按根因归入七个类别

工具调用失败的原因多种多样——文件不存在、搜索无结果、网络超时、权限不足、参数格式错误。如果只把原始错误信息传回去，Agent 需要自己从报错文本中推断根因并制定修复策略，而模型在解析长错误信息时的准确率不够稳定。

Peri 为每个核心工具定义了一个**错误分类器**——工具返回失败后，分类器根据错误码、返回内容和工具类型，将失败归入七个标准类别，分别是文件不存在、路径歧义、权限不足、网络超时、参数格式错误、内容未匹配、外部服务不可用。每个类别关联了一组预设的修复策略。分类结果是确定性的——同一个工具、同一种失败、同一个分类，不依赖模型判断。

分类器的核心价值是降低了 Agent 的理解成本。Agent 不需要解析 Bash 命令的 stderr 全文来推断是不是权限问题——分类器直接告诉它是权限不足，附带建议检查文件权限或切换路径。分类后的信息长度控制在 200 字符以内，远短于原始错误输出可能的上千字符，不占用过多上下文窗口。

## 建议生成器根据失败次数升级干预强度

同一个工具在同一个文件上反复失败，意味着 Agent 的修复策略无效。Peri 按失败次数分级升级建议——

首次失败时，建议是提示性的，附带两个信息——具体失败原因和推荐的修正方向。比如参数格式错误时建议检查必填字段是否传入，内容未匹配时建议用 Read 工具重新读取文件。

同一工具在同一目标上连续失败 3 次后，建议升级为指令性——不再给推荐方向，而是给出具体的操作步骤。比如编辑工具连续 3 次 old_string 未匹配，建议变为先执行 Read 工具读取目标文件的最新内容，然后基于最新内容重新构造 old_string。Agent 直接执行步骤即可，不需要自己制定策略。

连续失败 5 次后，框架判定 Agent 已陷入死循环，不再注入建议而是注入一条停止消息——告知 Agent 该操作路径不可行，建议换一种方式达成目标，或请用户介入。这 5 次上限是实践证明的平衡点——少于 5 次可能漏杀（Agent 差点就成功了），多于 5 次则浪费 token 且用户不耐烦。

## 纠正消息在工具结果收集完成后单独注入

纠正消息的注入时机经过了两版调整。早期版本在工具失败时直接把纠正消息追加在工具结果后面，作为同一条 User 消息的一部分。这导致了一个问题——如果一次 Act 阶段同时调用了 3 个工具（如 Read、Grep、Edit），其中 2 个成功 1 个失败，Agent 看到的消息是成功结果、成功结果、失败结果+纠正建议的拼接体。模型容易把注意力集中在两个成功结果上，忽略夹在中间的纠正建议。

后来改成在工具结果全部收集完后、下一轮推理开始之前，作为一条独立的纠正消息单独注入。纠正消息使用 **Human 消息类型**而非 System 消息——System 消息会被 Anthropic provider 的 System hoist 机制提升到静态 prompt 段，破坏前缀缓存。Human 消息作为普通对话消息追加在末尾，不影响 prompt cache 的稳定性。

分离注入的另一个好处是 Agent 对纠正消息的重视程度显著提高——独立消息在对话序列中有专有的位置，模型不会把它和工具结果混在一起解读。内部测试显示，独立注入后 Agent 对纠正建议的采纳率从 68% 提升到 91%。

开头的 old_string 连续 3 次失败的场景，正是错误分类、升级建议和独立注入三道机制协同作用的结果。Peri 从 74% 到 93% 的工具调用成功率提升，不来自 Agent 变得更聪明，而来自框架在 Agent 即将走偏时拉了一把。
