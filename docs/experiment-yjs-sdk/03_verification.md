# 验证报告 3：每批转换 V2 的最终候选

状态：独立静态验证完成。审查 [实验 3](03_experiment_report.md)、[final 原始结果](raw/final/summary.json)、[实际 demo adapter 补采](raw/final-sse/summary.json) 及对应源码/harness 归档；没有重新运行性能基准。组合场景另见 [验证 4](04_verification.md)。

## 总体评估

**PASS**。最终冻结候选的原四场景 12 个样本与实际 JSON/base64 adapter 的 3 个补充样本均完成，数据、精确内容校验、统计与来源记录一致。工具投影和大历史视图更新的改善可信；纯流式实际 demo 路径应表述为**接近基线**，不将约 3.16% 的差异解释为显著加速。

## 数据完整性：PASS

逐个样本 JSON 与 summary 完全一致，15 个样本均 `passed`、子进程 exit 0、无中止原因，未超过 120 秒和 2 GiB 预算。Bun 1.4.2、Yjs 13.6.33、锁文件及生成器指纹均匹配前两轮。所有最终候选样本的源码指纹相同：`96800d1a6c1be32cb460a8b85be68788a8410f5bc5215dd4eb3d8c5e16ebbb67`。

三个 tools 样本均通过冷副本公开视图校验：12,000 个工具、1,200 个历史 assistant、顺序、归属、参数、结果和 completed 均正确；12,000 次引用读取合计各 98,964,890 bytes。三个 view 样本的初始/最终历史保持完整，128 次发布均保留首工具身份，128 KiB 新文本精确；原始延迟数组的总和、中位数及 p95 均匹配汇总，真实工具更新与旧快照检查保留。

native 与实际 adapter 共六个流式样本都完成 16,384 个分片，最终文本为 16,777,216 bytes，实际/预期 SHA-256 均为 `732dd2b3f284d2273326b8acf57f014a895f513bfc79770eb963226aeaef8cb6`，接收端公开视图终态 completed。完成 flush 各发送 1 帧。1 MiB 结果的热快照约 2,779 bytes，仍另外精确读取 1,048,634 bytes 全文 JSON。

## 方法正确性：PASS

本轮冻结代码确实收集 `update` V1 事件，合并后每批调用一次 `convertUpdateFormatV1ToV2`；对外仍应用 V2。与第二轮相同 native 路径比较时，原始计时区间和生成器保持一致；中位数 **226.443 → 169.106 ms**，下降约 25.32%，支持这次编码策略修订。

实际 adapter 补采修复了第二轮路径比较的缺口：脚本调用冻结 demo `SessionDocStream`，接收端实际执行 base64 解码，再调用副本 apply。与基线相同，JSON 序列化用于 body 字节计数，未模拟 HTTP/SSE socket、JSON.parse、网络延迟或浏览器绘制。这里的“实际 SSE 路径”是实际 adapter 的进程内路径，不是浏览器网络端到端基准。

双方 `endToEndMs` 均覆盖 user、生成文本、全部接收、completed 和副本 apply；候选额外显式 flush 并等待 close。初始冷快照、最终全文校验位于该区间之外。该值来自墙钟计时；不能把接受分片的累计耗时或 apply 单项替代完整耗时。

每个采样命令的 runner 等待 `child.exited` 后再启动下一样本，原始记录时间区间也未发生相互覆盖。正式 final、final-sse 及后续组合样本共 21 个记录区间彼此不重叠。静态材料可以核对实验进程顺序，不能独立证明操作系统上没有任何其他进程；排程 provenance/执行记录与已披露的重叠排除记录共同限定这一证据。

## 结论合理性：PASS

独立重算得到以下三次中位数；报告均值、样本标准差和比例也匹配原始数据：

| 指标 | 增强基线 | 最终候选 | 解释 |
| --- | ---: | ---: | --- |
| 12k 工具投影 | 1,740.883 ms | 143.534 ms | 本工作量约 12.13 倍加速 |
| 128 次视图总耗时 | 2,883.206 ms | 50.347 ms | 本工作量约 57.27 倍加速 |
| 视图单次经验中位数 | 22.101 ms | 0.338 ms | 三个样本的中位数再取中位数，约 65.41 倍 |
| 实际 adapter 流式完整耗时 | 186.797 ms | 180.902 ms | 约少 3.16%，应称接近基线 |
| 流式帧数 | 16,389 | 265 | 当前紧循环下减少 98.38% |
| 流式 JSON body bytes | 25,189,286 | 22,408,849 | 减少 11.04%，未计 transport framing |
| tools 峰值 RSS | 1,456.531 MiB | 1,289.750 MiB | 完整场景下降约 11.45% |
| view 峰值 RSS | 971.703 MiB | 1,074.063 MiB | **上升约 10.53%** |

实际 adapter 三次耗时为 184.435 / 180.902 / 176.971 ms，基线为 186.797 / 183.460 / 206.689 ms。样本少、未随机交错，不能由这组结果推断稳定的 3.16% 生产收益；native 的 169.106 ms 也不能替代公平的 adapter 比较。

热 V2 快照仍为 23,059,321 bytes，约比基线完整快照减少 80.12%；同候选 V1 热快照为 24,719,251 bytes，可区分载荷隔离和 codec 的共同作用。热快照加全部引用 JSON 仍为 **122,024,211 bytes**，比基线完整快照高约 5.21%。完整进程 RSS 也没有全部下降，报告未把默认同步改善误写成总数据或常驻内存等比例下降。

## 可复现性与报告质量：PASS

源码和原四场景 harness 的归档 SHA-256 均匹配，源码归档的 47 个文件、bridge 和锁文件逐项指纹一致；原四场景的七个 harness 文件也全部匹配 provenance。实际 adapter 使用扩展后的八文件 harness，来自 `final-combined/harness.tar.gz`，归档及逐文件指纹同样匹配。复现时需选择场景对应的 harness 版本，不能用原四场景的归档执行后来新增的 `stream-sse`。

报告准确保留了 view 内存回归及冷热总字节限制。一个小的元数据说明需要保持准确：原 `raw/final/stream-*.json` 没有后来新增的 `transport` 字段；其 native 路径由所在目录、`framing`/`timing` 和归档脚本识别。`final-sse` 样本有明确 `transport` 字段，证明调用了带实际 base64 编解码的 adapter。此元数据差异不改变测量结论。

## 上一轮反馈与剩余边界

第二轮的纯流式回归已通过相同 native 路径重新测量，实际 adapter 又补齐同口径比较；公开全文、完成边界及来源归档保留。冻结代码包含广播重入保护、各订阅者缓冲区所有权隔离和销毁入口保护，但吞吐样本本身不是这些生命周期契约的证明，仍以对应回归测试为准。

大历史叠加 16 MiB 输出不由本轮独立场景代替，已另用第四轮审查。多客户端、网络丢包恢复、真实定时到达、DOM 渲染和长期常驻内存也不从这些本地数据外推。本验证只新增文档，未运行构建、测试或性能基准。
