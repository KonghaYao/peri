# 对抗验证报告：SDK Yjs 存储与复制

日期：2026-10-05。独立审查综合结论、第三/四轮实验及验证报告，并阅读当前 `state`、`view`、`sync`、原始事件队列、Session 和 demo SSE 实现。本报告是本次实验的验证记录；公开契约以 [SDK README](../../npm-packages/@peri-sdk/README.md) 为准。

## 总结

对交付前实现的攻击发现 **两项真实的回调重入缺陷**：关闭期间错误接纳订阅，以及已取消发送者返回 Promise 时产生未处理拒绝。主代理已修复，独立复现脚本再次执行，两项均消失。其余小规模对抗场景未发现全文错配、恢复丢失或双文档序号错误。

性能结论在报告明确限定的合成工作量内仍成立。不能将其扩大为总存储缩小 80%、所有内存指标下降、真实网络吞吐提升 98%，或任意规模都能在 2 GiB 内完成。原报告已披露这些限制，无须通过隐藏不利数据保住结论。

没有重跑压力基准；本轮执行的是独立的小规模行为攻击。修复后的代码与性能冻结版本存在两处生命周期控制差异，性能数字仍属于第三轮冻结版本；详见 [交付检查](delivery.md)。

## 攻击 1：订阅过程中关闭 producer

- **目标结论**：关闭后不再接纳订阅，回调重入不会破坏生命周期。
- **攻击角度**：在 `subscribe()` 的入口检查之后，利用其同步 `flush()` 调用旧订阅者；旧订阅者立即调用 `close()`。
- **观察**：修复前，外层 `subscribe()` 仍成功返回，`admitted=true`。等待关闭后 update listener 数为 0；没有观察到残留监听或丢失既有数据，不能把这个缺陷夸大为已证明的内存泄漏。
- **严重程度**：中等。API 对已关闭 producer 给出错误的成功接纳结果。
- **处理及复验**：主代理在 flush 返回后再次检查 closed。原脚本复验得到 `admitted=false`、`Error: Yjs sync is closed`、listener 数 0；新增 `subscription admission fails if flushing an existing peer closes the producer` 回归测试。

## 攻击 2：发送者取消自身后返回拒绝的 Promise

- **目标结论**：订阅者错误被隔离，取消和异步发送可以安全组合。
- **攻击角度**：发送回调同步取消自身，再返回一个 rejected Promise：

```ts
const connection = sync.subscribe(() => {
  connection.unsubscribe();
  return Promise.reject(new Error("transport already aborted"));
});
chat.getText("text").insert(0, "x");
sync.flush();
```

- **观察**：修复前，`SyncPeer.pump()` 在发现 peer 已关闭后直接返回，未处理该 Promise。独立进程的 `unhandledRejection` 监听器捕获一次 `transport already aborted`；本实验捕获了错误，没有声称已经测得宿主进程崩溃。
- **严重程度**：严重。发送者的正常取消路径可越过错误隔离，形成宿主级未处理拒绝。
- **处理及复验**：主代理将返回 Promise 的拒绝处理放到同步 closed 检查之前。原脚本复验捕获次数为 0；新增 `a sender that unsubscribes before returning a rejected promise is still observed` 回归测试。

## 攻击 3：广播中途接纳副本并同时修改两份文档

- **目标结论**：跨文档共享序号与同步 snapshot admission 不会漏掉交界处更新。
- **攻击内容**：首个旧订阅者收到序号 1 时，在 chat 中追加 B，立即接纳新副本并应用返回的 snapshot，再修改 session 并请求 flush；原更新为 chat 的 A。
- **观察**：修复前后该攻击均未成功。新副本得到精确的 `AB` 和 session version 2，无序号间隙。广播期间新增 peer 不接收已经开始的那一帧，由 snapshot 和之后的帧补齐。
- **严重程度**：未形成缺陷。
- **建议处理**：保留广播重入、关闭重入与 Worker buffer 转移的既有回归测试；不由本例外推恶意乱序的控制帧也能自动恢复。

## 攻击 4：不可拆分的大更新与离线删除恢复

- **目标结论**：队列预算限制不会以静默丢失代替恢复。
- **攻击内容**：将订阅预算降为 64 bytes，写入单个 1,024 字符更新；随后以实际副本状态向量重连。再执行 60 次离线的双文档写入/删除/重连，每次逐对象比较源和副本。
- **观察**：超限显式报告 `SyncBackpressureError`；重连 snapshot/delta 精确保留 1,024 字符。60 次离线循环全部相等，没有以只比较 state vector 的方式遗漏删除。
- **严重程度**：未形成缺陷。
- **适用边界**：初始或恢复快照仍可能超过增量预算；本行为证明能够恢复，不证明快照和全文内存有统一上限。现有结论已明确这个边界。

## 攻击 5：载荷外置是否偷偷丢弃全文或返回其他版本

- **目标结论**：引用可精确读取当前完整 JSON；退休引用不会指向新内容。
- **攻击内容**：对同一个已完成工具连续写入 30 个大结果版本，每个包含 2,500 个 Unicode 字符及不同版本前缀；每次经公开视图取得引用，读取并精确比较 JSON，同时重读全部旧引用。最后销毁 SessionDocs。
- **观察**：30 个当前版本全文全部相等；所有旧引用和销毁后的引用均返回 unavailable，没有错误返回其他版本。旧引用失效属于明确契约，读取历史快照引用的客户端必须接受 unavailable 并刷新状态。
- **严重程度**：未形成缺陷。
- **边界**：上述测试不证明持久化 blob 服务存在；完整结果仍保存在 host 内存，重启依赖 canonical ACP 历史重建。

## 攻击 6：把数据转移误报成总存储下降

- **目标结论**：默认热快照减少约 80.1%。
- **攻击角度**：若把大结果排除在测量之外，用户读取所有工具结果后可能没有节省总字节。
- **核查**：综合结论和第三轮均明确列出 98,964,890 bytes 完整外置结果，以及热 V2 加结果共 122,024,211 bytes，比旧完整快照多约 5.21%。view 峰值 RSS 增加约 10.53% 也保留在结论中。这个攻击成功否定“总体存储/内存同幅下降”的扩张解释，没有推翻“默认热同步缩小”的实际结论。
- **严重程度**：若省略这些边界则严重；当前报告已充分限定。
- **建议处理**：最终交付摘要使用“热快照”，勿省略“热”字；不保证大量同时展开工具、多副本或超长常驻会话的总内存收益。

## 攻击 7：紧循环实验是否冒充网络吞吐和统计显著性

- **目标结论**：流式帧数降低 98.38%，实际 adapter 纯流式耗时接近基线，组合场景在预算内完成。
- **核查**：脚本确实经过实际 demo adapter 的 base64 编解码和副本 apply；不包含真实 socket、JSON.parse、浏览器绘制或逐块真实到达节奏。16 ms 定时到达下的批量数量可能与紧循环不同。三次非随机交错样本不支持将约 3.16% 的耗时差宣称为显著加速。
- **观察**：报告已经将纯流式描述为接近基线，并注明帧数属于该工作量；组合基线三次因预算截断且没有最终全文校验，报告没有从前缀计算完整加速比。与 build/test 重叠的早期组保留并明确排除，第二轮耗时回归也被保留。未发现通过删除不利样本制造结论的证据。
- **严重程度**：中等外部效度限制，已披露，不构成当前限定结论的反证。
- **建议处理**：继续将这些结果表述为本地合成负载；真实网络、长期 heap 和多客户端容量需要各自场景，不能从本实验直接推出。
