# Peri 3.0 架构大重构（伞形 PRD）

**状态**：Ready for agent
**标签**：`ready-for-agent`、`3.0-refactor`、`architecture`
**优先级**：高
**类型**：重构
**创建日期**：2026-08-05
**来源**：`docs/top-level.md` v3.9（commit `6616e477`，唯一基准）+ 两轮对抗审计（`.peri/plans/perihelion-model-agent-layer-adversarial-audit.md`、`.peri/plans/audit-middleware-resources.md`、`.peri/plans/` 下 Runtime/Controller/ACP/TUI 审计）

## Problem Statement

当前 v2.x（workspace 版本 0.2.0）的依赖结构与运行时组织违反 3.0 目标分层，且问题已被审计证实：

- peri-acp 直接依赖 6 个业务 crate（含 peri-middlewares），1200 行装配 builder 与 3700 行 langfuse 内嵌其中——协议层承载了全部业务装配与观测。
- peri-tui 进程内嵌整个控制面：直连 `run_session_loop`、两处直接实例化 `SqliteThreadStore`、v2_tx 双轨直连 Agent 事件（绕过 ACP caps 门控）。
- `BackgroundTaskRegistry` 是进程级全局单例 + 单 session 槽位（`peri-middlewares/src/subagent/background.rs:135`），多会话下任务互相干扰。
- `SubAgentMiddleware` 24 字段、约 4600 行、4 条执行路径——v2 越层最重模块。
- print 直连 `run_session_loop`，行为与 TUI 不经同一协议路径。

从使用者视角的后果：IDE/print 等客户端无法以协议接入完整能力；多 session 下 bg 任务生命周期互相污染；取消语义不稳定（cancel 不清队列、幂等/优先级未契约化）；同一事件经双轨投递后身份漂移（工具卡重复、SubAgent 路由丢失 source_agent_id）；层边界无法用依赖方向验证，改一层必须理解全部层。

## Solution

按 `docs/top-level.md` v3.9 将 workspace 重构为七层：`Model → Agent → Runtime → Controller → ACP → TUI`，支线 `Middleware / Resources`。新建 `peri-runtime`（薄编排器）、`peri-resources`（外部系统门面，内含 peri-config/peri-sessions）、`peri-controller`（控制面 + Langfuse bridge 宿主）；`peri-acp` 瘦身为纯协议（映射/caps）；`peri-agent` 扩展为 session 聚合根（生命周期容器 + async tasks + frozen + 装配 + cancel 执行权）；全部客户端（TUI/CLI/stdio/IDE/print）一律经 ACP。§9 时序契约（身份标识/cancel/MQ/session 销毁/持久真相/错误模型）固化为层间接口与契约测试；§0 依赖方向进 CI。重构不改变协议可见行为与业务语义，只做归位。

## User Stories

1. As a TUI 用户, I want bg 任务（shell/fork）跟随 session 生命周期创建与销毁，so that 多会话下任务取消、超时、事件不会互相干扰。
2. As a TUI 用户, I want cancel 幂等且按 (session_id, turn_id, attempt_id) 判定，so that 重复取消或迟到取消结果一致，turn 终态唯一（Completed 或 Interrupted）。
3. As a TUI 用户, I want cancel 不默认清除消息队列、可带 clear_queue 标志，so that 取消不等于丢失待办，续跑以队列为输入。
4. As a TUI 用户, I want 取消后已排队的 resume/promote/retry 全部失效（优先级 cancel > 续跑 > promote > retry），so that 取消语义不被后续指令翻转。
5. As a TUI 用户, I want 事件携带稳定身份（turn_id/agent_id/session_seq 单调），so that 工具卡、消息归组、SubAgent 路由不错乱、不重复。
6. As a TUI 用户, I want 重启后遗留 Running/Creating 任务记录被标记为中断，so that 状态不会永久悬挂。
7. As a TUI 用户, I want subagent 父子链通过 parent_thread_id 持久化（thread_id = agent_id），so that 会话回放可追溯。
8. As a TUI 用户, I want 空白 prompt 的 keepgoing 语义与取消短路在各 transport 行为一致，so that 不会卡在 loading。
9. As an IDE 客户端作者, I want 以 ACP 协议接入完整能力（事件/cancel/session 生命周期），so that 不依赖 TUI 进程或业务 crate。
10. As an IDE 客户端作者, I want 事件只有协议化单一事实源（无业务 DTO 双轨），so that 客户端实现只需跟随一份契约。
11. As an IDE 客户端作者, I want 多客户端 attach 采用多读者 + 单 writer lease，so that 观察者与操作者并存且写入不冲突。
12. As a print 用户, I want print 经 ACP 走 ephemeral session 轻量渲染，so that 行为与 TUI 一致且不造 sessionless 特殊路径。
13. As a 中间件作者, I want 统一 MiddlewareHook trait 抽象，so that 切面 = hook 挂载 + 工具声明 + prompt 贡献 + 条件守卫，模式单一。
14. As a 中间件作者, I want 外部依赖一律经 Resources context，so that 中间件不直接触碰外部系统（配置/sqlite/MCP/secret）。
15. As a 中间件作者, I want bg 任务只做定义与启动发起（经 Agent 层 TaskManager 接口），so that 切面不持有生命周期管理权。
16. As a 中间件作者, I want 链装配顺序事实源唯一且随装配迁至 Agent 层 session 工厂，so that ARC-MIDDLEWARE-001 不被破坏。
17. As a subagent 使用者, I want 所有 subagent 创建统一走 `SessionFactory::spawn_subagent(parent, config)`，so that 4 条执行路径 + /bg 命令行为一致。
18. As a 维护者, I want crate 依赖方向由 CI 校验（§0 边），so that 越层依赖在合入前被拦截。
19. As a 维护者, I want 错误边界类型化且仅三类（终止类/可重试类/协议错误），层内 anyhow，so that 错误语义不随层漂移、`?` 不误报。
20. As a 维护者, I want Runtime 无状态、唯一持有 session_id → SessionHandle 映射，so that 多 session 编排可推理。
21. As a 维护者, I want session 销毁顺序契约化（停收新输入 → 取消 owned tasks → join(deadline) → abort → 持久化收束 → drain 事件 → 移除映射），so that 无泄漏无悬挂。
22. As a 维护者, I want Thread/transcript 为持久真相、Task 为易失投影，so that 重启语义可预期。
23. As a 观测者, I want Langfuse bridge 是事件流旁路消费者（装配在 Controller 侧宿主），so that 观测不参与业务链路、不承担 Controller 职责。
24. As a 观测者, I want 观测事件靠身份牌 (session_id + turn_id + agent_id) 关联，so that 跨层可追踪且不改变业务链路。
25. As a 用户, I want 消息模型统一为 MessageType（Human/Ai/Tool/SystemReminder，v2 BaseMessage 更名），so that 协议消息与业务消息不混淆。
26. As a 用户, I want 模型/AgentGroup（agm 理念）会话语义在重构后行为不变，so that 重构零功能回归。

## Implementation Decisions

以 `docs/top-level.md` v3.9 为唯一基准，以下为关键决策摘要（不复制正文）。未决项给出推荐并标注「排期时确认」。

1. **新 crate 归位**：`peri-runtime`（薄编排器）、`peri-resources`（内含 peri-config/peri-sessions 子模块）、`peri-controller`（控制面）；`peri-acp` 瘦身（协议/映射/caps）；`peri-agent` 扩展为 session 聚合根；`peri-acp-types` 保留为接口契约层。
2. **依赖方向 CI 门**：§0 crate 边以 workspace 脚本或 cargo-deny 进 CI 验证（Seam 3）。
3. **Agent = session 聚合根**：Session 创建/运行/销毁全生命周期、AgentGroup、frozen data（session 创建时从 Resources 拉磁盘数据冻结，subagent 创建时 copy）、Session 级 hook、MessageQueue、RCRA 循环（Receive 为唯一退出口）、cancel 最终执行权均归此层。
4. **BackgroundTaskRegistry per-session 实例化**：定义与实现迁入 peri-agent，随 session 创建/销毁（生命周期/取消/事件跟随 session）；Middleware 仅经 TaskManager 接口发起。
5. **Middleware 只定义与发起**：Hook trait + 工具声明 + prompt 贡献 + 条件守卫；bg 任务定义与启动发起（调 Agent 层 TaskManager 接口），不持有管理权。
6. **Resources 门面**：peri-config 直操配置文件；peri-sessions 直操 sqlite（SqliteThreadStore 实现迁入）；MCP 状态、HITL broker、secret；以 context 形式提供给 Agent / Middleware / Controller；不解释业务语义。
7. **Controller 控制面**：lite params → pick Resources → pick Runtime → run Session → pop events；cancel 只定位与转发（Controller::cancel(session_id, policy) → Runtime 查映射 → Agent 判定 → Model 中止）；事件聚合/过滤在协议化前出口。
8. **ACP 纯协议**：事件协议化映射、caps 门控；全部客户端（TUI/CLI/stdio/IDE/print）一律经 ACP。
9. **身份标识**：跨层消息统一携带 (session_id, session_epoch, turn_id, attempt_id)；epoch/attempt_id 不可复用（防迟到消息命中新 session）。
10. **事件契约**：事件携带 turn_id + agent_id；session_id 由 Runtime 聚合时按 session 补打（Agent 层事件不携带）；同 session 事件带单调 session_seq；terminal 事件必须位于该 turn 全部输出事件之后。
11. **cancel 契约**：幂等（针对三元组）；优先级 cancel > 续跑 > promote > retry，cancel 后已排队的 resume/promote 失效；cancel ≠ 清除待办（MQ 未消费消息保留，随下次循环消费作为新 attempt 输入；可带 clear_queue 标志默认 false）。
12. **session 销毁顺序**：停收新输入 → 取消 owned tasks → join（带 deadline）→ 超时 abort → 持久化事务收束 → drain 事件 → 移除映射。
13. **持久真相**：Thread/transcript 持久；Task 易失投影；重启不复活 Task，遗留 Running/Creating 记录标记为中断。
14. **错误模型**：边界 thiserror 枚举逐层包 context，层内 anyhow 穿透；仅三类必须类型化——终止类（cancel/interrupt，防 `?` 误报失败）、可重试类（rate limit/超时，重试策略用）、协议错误（ACP 序列化用）；TurnError 语义保留 Agent 层。
15. **compact**：RCRA 阶段归 Agent，token 计数经 Model。
16. **消息统一**：MessageType（Human/Ai/Tool/SystemReminder，v2 BaseMessage 更名）；3.0 不合并消息类型（Model=协议消息、Agent=业务消息）；协议转换在 Reason 阶段。
17. **Langfuse**：桥为事件流旁路消费者，装配在 Controller 侧宿主；采集点分散各层（Model token/调用、Agent stage/turn、Controller 操作、ACP 事件）；观测事件随主事件流在协议化前分支。
18. **HITL/secret**：broker 经 Resources 注入 Middleware（OnPermissionRequest 在 Middleware）。
19. **部署形态**：层 ≠ 进程；ACP Host = 部署单元；print 用 ephemeral session（不造 sessionless）。
20. **既有 crate 归位**：peri-lsp / peri-workflow 作为 resource 实现接入 peri-resources（包装为 context），不参与分层主链；peri-web-pty 归 TUI 层 CLI 命令；acp-hub 为 side project 不写。
21. **未决项推荐（排期时确认）**：
    - **executor 拆分**：build_*（session/装配构造）归 Agent 层 session 工厂；RCRA 9-phase loop 归 Agent（§2 已明确 RCRA 归 Agent 层）；executor.rs/helpers 中与 ACP 相关的协议化入口留 ACP 薄壳；Controller 只经 Runtime→SessionHandle 发起 run Session。
    - **stdio server 宿主**：归 ACP 层（ACP Host = 部署单元），由 cli/TUI 作为部署装配点启动。
    - **provider 工厂/模型缓存**：provider 配置通道归 Resources（来源为外部配置）；模型实例创建归 Model 层（协议适配）；实例持有按生命周期——进程级复用缓存归 Controller 侧宿主或 Model 层，session 级归 Agent 装配。
    - **多客户端 attach**：多读者 + 单 writer lease（writer 唯一可提交输入/取消）。
    - **§9 层间接口签名**：在 peri-acp-types 定义 canonical identity / cancel request / 事件 envelope 类型，各层接口引用这些签名（语义已有，签名待补）。
    - **错误边界枚举名**：AgentError / RuntimeError / ControllerError / AcpError（沿用审计候选，仅三类类型化）。
    - **TUI 内嵌 server 迁出形态**：迁出为独立 ACP host 装配（cli 启动），TUI 仅作 ACP 客户端，进程内不再持有控制面。

## Testing Decisions

测试 seam 方案（已与用户确认，三 seam）：

1. **Seam 1（最高、既有）：e2e 行为基线** —— 复用 `e2e/tests/scenarios` + ACP stdio transport。重构不改变协议可见行为；每个迁移点合入前保持整套 e2e 绿。这是最高 seam，覆盖用户可见行为整体。
2. **Seam 2（新建、层边界）：§9 时序契约测试** —— 在 peri-acp-types 或各层 tests/ 固化为契约测试：身份标识 (session_id, session_epoch, turn_id, attempt_id) 不可复用、cancel 幂等/优先级/不清除 MQ、session 销毁顺序、session_seq 单调、terminal 事件位置、错误边界枚举语义。先于或随 executor 拆分（L5）落地。
3. **Seam 3（新建、CI）：§0 依赖方向校验** —— workspace 依赖图脚本或 cargo-deny，作为 CI 门。

测试原则：只测外部行为不测实现细节（`docs/design/testing-standards.md` P0 分层）；外部 API 用 mock 替换 trait 接口；移动模块时单元测试随迁（background registry、builder 装配、langfuse 消费、executor 拆分），不重写既有断言语义。Prior art：现有 ARC-* 契约的 Verify 列测试、e2e/tests/scenarios、各 crate `*_test.rs` 随迁模式。

## Out of Scope

- ACP 协议版本升级：重构不改 wire format，保持既有协议兼容。
- TUI 视觉/交互重设计（仅迁出控制面，渲染职责不动）。
- acp-hub（side project，不写）；`side-projects/` 全部。
- 业务语义变更：goal/workflow/FS/HITL 等业务模块仅归位，不改行为。
- 性能调优（分层带来的自然变化除外）。
- 多客户端 attach 的协议级扩展（策略先行，协议扩展另立 issue）。
- FrozenContext 生产路径空 build()、死 hook（on_session_start/end 0 生产调用方）等审计发现的清理，随各子 issue 顺带处理，不单独立项。
