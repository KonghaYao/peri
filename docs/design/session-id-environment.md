# Session ID 恢复与机器环境分区

> 状态：已批准目标设计，尚未落地。
>
> Scope：共享后端数据库中的会话身份、机器环境分区与恢复入口。
> 进度与验收见 [核心改动清单](../../spec/issues/2026-09-30-session-id-environment-core-change.md)。
> 本目标取代旧工作区设计中以目录绑定、文件锁和根执行 owner 限制恢复的规则；父子关系与运行资源生命周期保持。

## 核心裁决

1. **Root session 以 ID 标识，不归属于持锁机器或某个历史运行实例。** 在可访问的数据库范围内，持有 ID 的调用方可以查找和恢复会话；不要求先认领 owner。
2. **父子关系保持现有模型。** 子会话仍由 parent ID 关联，根会话通过父链确定，不以路径或当前终端重新归属。
3. **路径不是会话归属权。** 数据库中的 cwd、项目根及工作区路径只作为列表过滤、展示和工具定位信息；不能因为路径不存在或与当前机器不同而拒绝按 ID 恢复历史。
4. **execution_environment_id 标记机器位置归属，提供数据库中的 env 分区。** 它不是用户 owner、互斥锁或执行所有权凭证，不等同于 URI，也不要求全面 VFS。
5. **移除 session 执行文件锁及相应恢复弹窗。** 不以新的分布式锁、全局 owner 认领或 dirty 确认替代旧恢复门槛。

## 数据身份与查询

Session ID 保持唯一身份，不改为路径、机器地址或 env + path 复合主键。根会话记录 env 归属，子会话沿根关联获得归属；持久化是否冗余 env 字段由实现确定，但必须只有一份归属规则。

机器 env ID 应持久、跨应用重启稳定，不以进程 PID、瞬时连接地址或每次启动的 UUID 代替。同路径在不同 env 中分别登记和过滤，不共享本机文件对象证据。

建议的查询语义：

```text
list_sessions(env_id, optional_path_filters) → 该 env 范围内的列表
load_session(session_id)                    → 按 ID 读取会话及记录的 env
resume_session(session_id)                  → 不要求目录或 owner 认领
```

显式按 ID 访问不隐式追加“env 必须等于当前机器”或“cwd 必须等于当前目录”的归属判定。env 分区用于数据库归类及带 scope 的查询，不改变 ID 的含义，也不自动移动会话归属。

env 关联与迁移需要显式数据操作，不因某人在另一台机器打开会话就改写。来源明确的本机记录可迁移到本机 env；来源不明的导入数据不能全部盲目认领成当前机器。

## 恢复与实际工具执行分开

恢复是按 ID 重建历史和计算状态；工具执行需要可用的执行环境、工作目录及工具连接。没有可用目录或环境时，仍能读取/恢复会话，但实际工具调用可以报具体的环境不可用错误。

“路径只作过滤条件”针对会话身份及数据库恢复准入，不表示 Bash、Read、Write 不再需要实际路径。不得为了恢复成功，悄悄在当前机器对另一机器的同名绝对路径执行。

当前运行实例仍负责自身任务的取消、子任务关系和后台资源收尾；这是运行生命周期，不是数据库 root session 的持有权。移除的是 session 互斥锁与恢复认领门槛，不是取消所有 SQLite 事务、缓存锁或进程资源管理。

TUI 不再展示执行占用/dirty 认领恢复确认，不再通过确认后调用 reset_dirty 才恢复。普通工具授权、删除确认等非该恢复机制的弹窗不在移除范围。

## 保证边界

- 本设计不承诺多台机器同时运行同一 session 时只有一个执行者；不再用文件锁或全局 owner 提供该保证。
- 数据库仍需保证单次写入事务及已有幂等契约。并发续写的冲突语义必须显式确定，不得把旧锁删除后宣称已解决并发工具副作用。
- Session ID 的可查找性不自动成为安全认证；env 分区也不等于面对恶意客户端的权限隔离。外部数据库/服务访问授权保持独立，不能仅靠终端过滤宣称多用户安全。
- 全面 URI/VFS、插件系统与 MCP 缓存迁移不是前置条件；插件与缓存继续现有落盘实现。
