# #446 权威与职责边界对抗

## 第一轮（初步盘点后）

方案：根承载理念与路由，standard 维护长期边界，设计维护当前/目标方案，功能登记与证据分别维护。

| 意见 | 决策 | 理由与落地 |
| --- | --- | --- |
| 根正文 13,268 字节，复制分层清单与工程规则 | 采纳 | 根收敛为理念与路由，AGENTS 继续指向同一 CLAUDE；降低重复漂移 |
| “不做冷恢复”会遮蔽后续批准的 work_state 新运行 | 采纳 | async 文档限定旧任务/执行身份；索引补 durability，保留目标和验收缺口 |
| async-only 后仍描述新 sync 的写入意图与身份规则 | 采纳 | 去掉新同步运行规则，历史 sync 仅作为迁移对象；resume 回链现行后台契约 |
| TUI 设计禁止组件 crate 写入 | 采纳 | 改为业务在 TUI、无业务组件在 components；不改运行时 |
| SDK/Rivet 专用装配缺中央路由 | 采纳 | 加原位设计链接和 Rivet 真实运行验收缺口；不复制第二套 owner 表 |
| durability 混入实施顺序和 SQL 仿真结果 | 采纳 | 移至 active 验收追踪，明确历史记录未在本轮重跑 |
| SDK OWNERSHIP 相对路径少一层 | 拒绝 | 实际 @peri-sdk 是单个目录名，原路径正确；没有保留无效修正 |
| 将所有设计集中成新总文档 | 拒绝 | 会制造迁移成本与重复权威，保留有效领域设计原位 |
| 批量删除所有含旧名的文本 | 拒绝 | 历史兼容、退役说明与目标缺口仍有价值，按语义核对 |

第一轮实际处置见 [全量清单](../../docs/verification/authority-inventory-446.md)。
未变更运行时行为、数据库表结构或外置 E2E 编排。

## 第二轮（修改后交叉审查功能目录与验收映射）

| 意见 | 决策 | 高 ROI 修正或拒绝理由 |
| --- | --- | --- |
| 分组批量来源不等于真实权威定位 | 采纳并交功能作者 | Monitor、时间、组件、Memory、MCP cache、Git watch 应回链各自真实契约，不能只保证路径存在 |
| 缺少进入会话后按 work_state 新运行的独立恢复能力 | 采纳并交功能作者 | MQ 不恢复旧执行的边界不覆盖根范围、child 装配和工作意图；补独立记录 |
| 所有证据只指目录和“待测试仓对账”太弱 | 采纳并交功能作者 | 现有验证函数/测试文件应可定位；仍明确本轮未复验，不伪造动态通过 |
| 未得到旧五级定义却直接宣称权威分级完成 | 采纳为交付限制 | 现稿已经标提案；缺旧裁决应保持明确缺口，不能隐去 |
| 对每个组合参数再造能力 ID | 拒绝 | 独立用户边界才登记，避免表格数量驱动过度拆分 |

二轮交叉复核还指出根压缩不应丢失已批准目标；已保留 1000 Agent 吞吐、Peri Loom 优先后端与 Community Swarms 规划边界，明确目标未验收。

二轮不新增运行时 owner；不为目录完整而补造运行时行为或测试结果。
