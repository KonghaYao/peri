# Subagent 与后台任务

按 [总目录](README.md) 的编号执行。为每个子任务设置不同的工具名、输出标记与完成顺序。

1. **P0-18 Subagent 详情显示真实记录**
   1. 启动会产生推理、正文和工具调用的 subagent，在运行中打开详情。
   2. 检查正文显示真实记录与工具结果，完成后关闭并再次打开。
   3. 确认终态内容仍可读，不为空白，也不混入父会话或其他子任务内容。
2. **P0-19 并发子任务按身份归属**（[issue](../../../spec/issues/2026-10-06-p0-subagent-display-identity.md)）
   1. 同时启动三个同名、输出标记不同的 subagent，并让后启动者先结束。
   2. 查看各 Agent 卡片与子任务组，随后恢复其中一个 child 并重开详情。
   3. 核对每组只含自己的工具行；恢复调用与旧组独立，完成顺序不交换名称或结果。
3. **P0-20 子任务运行时新 prompt 不上移**
   1. 让父回合显示助手正文，同时保持 subagent 运行。
   2. 提交或投递新 prompt，检查旧正文、子任务组、新气泡的先后顺序。
   3. 继续送达子任务事件并归档；原组仍更新，工具记录不丢失，顺序不变化。
4. **P0-21 后台结果自动回送父任务**（[issue](../../../spec/issues/2026-10-09-subagent-callback-chain-audit.md)）
   1. 启动后台 agent 或 fork，让子任务产生唯一结果，期间不再输入。
   2. 等待子任务终态和父任务后续回应。
   3. 核对唯一投递身份及父模型请求；结果无需新 prompt 即被处理，且只处理一次。
5. **P0-22 切换会话隔离后台任务**
   1. 在会话 A 启动后台子任务，切到会话 B 后让 A 的任务完成。
   2. 检查 B 的消息区，再返回 A 查看任务详情。
   3. 确认 B 不显示 A 的卡片或结果；A 保有正确终态，切换不取消或复制结果。
6. **P0-23 子任务详情可滚动且位置独立**
   1. 生成超过一屏的 subagent 详情，记录主消息区滚动位置后打开弹窗。
   2. 用滚轮、拖拽和键盘浏览详情首尾，再关闭、重新打开。
   3. 核对正文与滚动条同步且记录完整；主区位置不变，背景不接收弹窗滚动。
7. **P0-68 子任务提交时处理未结束的后台 shell**
   1. 让一个 subagent 通过 workspace Bash 执行记录自身 PID 后 `exec sleep 180` 的命令（`run_in_background: true`）；取得后台任务 ID 后立即尝试提交最终结果。
   2. 核对 child 在等待 shell 自然退出前收到一次包含该任务 ID 与运行状态的 SystemReminder；提醒仅提供任务事实，不代替模型决定后续操作。
   3. 让 child 用普通 Bash 对记录的进程组发送终止信号，核对进程退出、原任务 ID 进入终态，child 随后提交并释放运行登记，父任务只收到一次结果；不得重复提醒或一直显示运行中。
8. **P0-69 子任务流断提醒只由 child 消费**
   1. 在父会话启动一个会产生正文与工具调用的 subagent，用本地可控服务让 child 的模型流在已输出部分正文或工具参数后中断（连接未正常结束）；父回合保持运行，TUI 停留在父会话。
   2. 核对父视图消息区出现一次该提醒（必达提醒：Guidance / model_runtime / Warning），父回合不被重启；父模型后续请求与重载后的父 transcript 均不含该提醒，提醒只持久于 child transcript。
   3. 核对 child 在下一轮 Receive 从断点续跑：不重复已输出内容与已完成工具调用，被截断的工具调用重新发起并成功提交，父任务只收到一次最终结果；child 详情中该提醒可查，重载后归属不变。
   4. 展开父视图中的该提醒，核对展开内容标注转发来源与状态（转发自子任务 `{name}` · 由该子任务继续处理）；折叠态标题与本地提醒一致、不显示归属标注；子任务展示名未能解析时回退显示 child_thread_id。
9. **P0-70 并行后台任务的活跃状态与静默可判定**
   1. 同时启动两个后台 subagent，让其中一个持续产生工具调用与正文，另一个在启动回执后不再产生任何事件；等待期间不提交用户输入。
   2. 持续观察后台任务栏与两个任务的详情：核对两条任务行各自独立（名称、摘要、耗时分开），有事件的一行随真实工具活动更新；静默的一行不得显示为已完成或失败，也不得凭空出现新的工具行、工具计数或进度。
   3. 核对两个任务的事件与 `session/bg-tasks` 快照：界面上显示的最后一条活动都能在该任务的事件中找到对应，静默任务没有伪造的新活动；耗时按真实时钟推进但不代表进度，其最后一条真实记录仍可在详情中查到。
10. **P0-71 后台子任务传输故障耗尽后不静默**
   1. 用本地可控模型服务让一个后台 subagent 的模型请求持续返回传输错误（如 http2 stream error），重试耗尽后失败（单次中断后续跑属 P0-69 的范围）；父会话与任务栏保持可见，期间不提交用户输入。
   2. 核对屏幕：该任务行转为失败终态而不是继续显示运行，耗时冻结；详情与父会话提示保留重试耗尽与底层传输原因，不被替换为泛化成功或空文案。
   3. 核对事件与请求：父会话在无新输入时收到一次该任务的失败结果并产生后续回应，同一 task ID 只结算一次；已完成的子工具不重跑，迟到事件不使任务复活。
11. **P0-72 排队消息回执不冒充已消费**
   1. 让一个后台 subagent 保持运行，由父模型向它发送一条带唯一标记的排队消息，随后让 child 消费该消息。
   2. 核对屏幕：回执在 transcript 可见并明确当前 action/status（排队不表示已读），排队状态下不显示为已消费或已完成；child 详情在它实际消费时出现带同一标记的新回合。
   3. 核对请求与事件：该消息只投递给原 child thread 一次；对已非活跃 child 的同类发送按其实际结果呈现，恢复执行产生的新运行不并入旧任务行，未被消费的消息不留下已处理的假象。
12. **P0-73 任务身份与线程身份呈现可区分**
   1. 启动一个后台 subagent，记录启动与排队回执中的 task_id、child_thread_id，并让第二个后台任务同时运行作为对照。
   2. 逐处核对 transcript（Inline 与完整内容）、后台任务栏、Tasks 面板和 SubAgent 详情中的两个 ID：标签与用途明确、不省略或互换、不被截断混淆；从任务栏点击和面板选择进入的详情对应当前所选任务。
   3. 核对请求与持久数据：进入详情依据的身份与事件中的 task_id 一致，详情内容属于该 child thread 的历史；task 身份与 thread 身份不指向同一存储实体，两个任务不因 ID 相近而串详情。
