# Peri 分析能力重建：本轮可行动结果

本轮重建了离线分析器与本地查看器，以当前 SQLite 结构、消息生产代码和合成契约测试重新核对口径。旧 skill、一次性脚本与旧报告仅作为调查线索。运行入口见 [README](../README.md)，方法边界见 [ANALYSIS.md](../ANALYSIS.md)。

## 数据基础

[质量检查](2026-09-13-foundation/quality.md)覆盖 10909 个会话、564115 条自有消息。历史数据存在旧消息结构、V1 envelope、工具调用双写和单独保存的继承快照；不能直接把 JSON 中的工具块数量当成执行次数。查看器统计不重复计入继承消息，离线分析还显式暴露解析冲突和配对缺口。

## 相邻窗口的描述性对比

比较可见主会话，按会话创建时间选择两个相邻的 12 天 UTC 半开区间。每个选中会话纳入其全部持久化历史；这里不是按工具事件发生时间分组。两组都没有解析错误、缺失结果或孤立结果。

| 观测 | 2026-08-20 至 09-01 | 2026-09-01 至 09-13 |
| --- | ---: | ---: |
| 会话数 | 269 | 204 |
| 已配对且状态已知的工具结果 | 21427 | 19891 |
| 显式错误结果 | 437 | 323 |
| ExecuteExtraTool → Workflow 错误 / 已知结果 | 4 / 39 | 24 / 61 |
| Agent 错误 / 已知结果 | 37 / 365 | 41 / 347 |
| StrReplace 错误 / 已知结果 | 未观测到调用 | 19 / 19 |

总体错误数量减少，但 Workflow 的错误比例从 10.26% 升到 39.34%。这说明只看总数会漏掉局部问题；它也不能证明某次代码变更引入回归，因为任务、模型、工具使用方式和用户介入都可能变化。完整分母、来源指纹、规则与百分点差见 [对比报告](2026-09-13-comparison/compare.md)及其 [JSON](2026-09-13-comparison/compare.json)。

## 优先复核方向

对近期三类错误各选择三个不同会话核查，共九个案例、五个唯一会话。选择方式是每类前三个合格错误会话，属于定向复核，不能估计整个错误群体的原因比例。

| 改进候选 | 已观察到的证据 | 下一步可验证动作 |
| --- | --- | --- |
| 历史工具名称与当前目录不一致 | StrReplace 的三个样例均返回工具不存在；当前文件编辑工具注册名为 Edit | 核对历史工具目录、提示词和别名迁移，构造名称解析 fixture，再决定修目录、迁移还是提示词 |
| Workflow 错误需要分层 | 三个样例中两个为 preflight 输入诊断，一个为 runner 启动/RPC 失败 | 分类全部 24 个近期错误，为 preflight 与启动链路分别设计复现；不要用统一重试掩盖确定性输入错误 |
| Agent 中断需要运行诊断支持 | 三个样例报告 stream interruption 或 retry exhausted；都存在后续成功活动 | 用稳定调用/会话标识关联 provider/runtime attempt 信息，区分模型流故障、重试耗尽和明确取消 |

九个样例的后续成功活动不等于原任务已完成，也不证明同一个工具已经恢复。当前数据库证据不足以推断用户满意度、完成率或 provider 根因。详细 message/call IDs、代码入口、观察与未验证项保存在 [核验报告](2026-09-13-validation/findings.md)和 [改进队列 JSON](2026-09-13-validation/findings.json)。

## 后续 agent 如何接着研究

先运行 `inspect` 检查数据质量，再用 `report` 明确研究范围；用 `sample` 获得可复现样本，用 `evidence` 按 message ID 回查邻近记录，最后以 `compare` 检查同一指标定义下的变化。

本轮另以固定 seed 从近期消息数至少 100 的 99 个合格主会话中抽出 8 个，保存在 [sample.json](2026-09-13-sample/sample.json)。这个样本供后续复核使用，本轮没有将未阅读样本计入结论。默认输出只有定位信息；正文与参数需显式选择输出，并限制在 64 KiB 内。缺少已知结果的比例保持空值，不能当作零错误。

查看器的验证包括本地 API fixture、真实库只读统计、首次 Dashboard、搜索、105 条合成消息的分页，以及断连后 Retry 恢复。分析器使用临时 SQLite fixture 验证旧/V1 消息、双写、继承、未知错误状态、范围、证据预算及报告口径。没有修改 Peri 运行时工具行为，本轮交付的是可信分析入口与可追溯的改进候选。
