# 任务关注点漂移与纠正吸收

状态：持续研究方向。研究标识：`RQ-FD-001`。本文件维护研究问题与复核口径，不是生产提示词或已验证的因果结论。

研究大模型在持续任务中，实际推进的对象、优先级和验收条件如何偏离用户当前有效目标；尤其关注用户反复纠正、要求返工，以及纠正后是否真正收敛。这里的“关注点”指可观察的行动与验证选择，不指模型内部 attention，也不推测用户未表达的心理意图。

数据读取、质量与证据规则继承 [ANALYSIS.md](ANALYSIS.md)，任务契约与独立评审继承 [TASK-EVALUATION.md](TASK-EVALUATION.md)，命令见 [README](README.md)。本方向只补充专题口径，避免另建数据解析器或任务总分。

## 持续回答的问题

- **目标在哪里变了？** 用户要的最终结果是否被局部改动、邻近问题或容易通过的检查替代？
- **纠正吸收到了哪一层？** 口头理解、下一次实际行动、验证条件、旧改动处置是否一致？
- **什么仍然有效？** 最新反馈加入后，先前未撤销的目标与约束是否继续受到保护？
- **何时只是正常迭代？** 区分需求细化、合法目标切换、普通实现缺陷、工具阻塞与持续偏离。

## 分析单位与判定

以同一任务内的“目标—行动—纠正—后续行动/验证”片段为单位；一个会话可有多个任务，一个任务也可能跨会话续跑。分别报告唯一会话数、任务数和片段数，不能互换。按用户请求和有效修改确定边界，不能以会话末尾标题替代原始目标。

本专题允许按纠正链选择任务，逐例声明读窗与选择理由，不默认套用批量任务评价的“首个实质请求”政策。无纠正对照使用“目标—行动—验证”片段，纠正吸收记不适用；关键历史缺失时记无法判断，不能标作无纠正。

| 判定 | 需要的证据 | 不足以成立的信号 |
| --- | --- | --- |
| 可观察目标偏离 | 当时有效的明确目标/约束，以及与其不一致的具体行动或验收选择 | 一句抱怨、工具失败、会话很长 |
| 纠正后重复偏离 | 同一明确约束已被纠正，下一次相关行动仍违背它，且没有有效改约 | 多条纠正分别谈不同问题 |
| 需求细化/目标切换 | 用户增加粒度、偏好或新任务；先前表述允许多种理解 | 把后来的明确要求追溯为早已明确 |
| 实现缺陷/验证遗漏 | 行动仍针对原目标，但覆盖条件或实现不完整 | 直接推断模型转移了目标或注意力 |
| 无法判断 | 目标、关键执行、图片、继承历史或后续结果存在缺口 | 用摘要、自述或沉默补成成功/失败 |

这些判定可在不同片段并存。返工是调查信号；只有可见的重做、回滚或重复修补才能记录为返工事实。没有可靠耗时与 token 数据时不估算返工成本。

每个片段保存最小证据卡：

1. 原目标、有效修改、仍有效约束、验收条件和观察截止点。
2. 出错/歧义的具体对象、触发条件与预期粒度，例如一个列表还是列表中的每一行。
3. 纠正前的行动、用户反馈原文、纠正后的下一次相关行动；新任务单独分段。
4. 验证是否覆盖用户触发条件，以及先前改动被保留、撤回还是无法确认。
5. 可见终态、反例与替代解释；每项结论分为 observed、candidate、unverified。
6. 来源快照/hash、会话与消息 ID、消息序位、角色、精确短引文、评审者和方法版本。

纠正吸收分别记录为 **已更新 / 未更新 / 无法判断 / 不适用**：目标理解、实际行动、验收条件、旧约束保留、旧改动处置。不合成一个总分；道歉不代替修改，测试通过不代替目标验收，请求提交不等于完整接受。

## 抽样与每轮交付

先冻结范围、来源与选样规则，再读案例。定向抽样用于寻找机制；同时从未命中候选的会话中固定 seed 抽取对照，检查漏检与正常迭代。候选可来自纠正词、明确失败反馈（如“修复无效”）、撤回/重做请求和原目标追问；这些只是召回信号，不能自动贴标签。

复用读取器保留 canonical 历史，区分真实用户反馈、系统注入、压缩摘要与子任务转述；核对正文中的裁剪提示，不能只信导出的截断标志。图片未检查时不得断言图中要求已明确。对关键主张安排独立评审，分歧回查原记录，不以多数票定论。

逐例披露评审者、单评/双评范围和协调者复核；分工阅读不同案例不等于对同一案例双盲复核，没有共同评审的案例不报告评审一致率。

每轮在本地忽略目录 `output/focus-drift-<date>/<run>/` 保存运行清单、选样理由/seed、冻结证据、原评审、裁决、简报和机器可读改进队列。续轮保留旧记录并标明新增与重叠案例；没有源数据时说明只能复核方法。发布前校验全部引用的所属会话、内容和 hash。

简报先给几条可理解的结论，再列支持案例、反例和仍缺的证据。每项改进候选保留稳定 ID、证据状态、问题/影响、指标与分母、证据引用、局限、当前入口、下一步验证及成功判据。研究授权不等于生产修复授权。

若报告比例，必须分别定义并披露：

- 偏离：可判断片段中的偏离数，同时展示全部片段与无法判断数。
- 同约束再次纠正：可见后续行动的明确纠正片段中，再次因同一约束被纠正的数量。
- 验收更新：需要更新且后续验证可见的纠正片段中，验证覆盖该纠正的数量。

上述比例仅描述所选样本。定向案例、同一任务的多次纠正以及未命中对照都不能直接给出总体发生率；历史比较还需控制任务组成、观测覆盖和模型/工具版本。

## 待检验假设与下一步

| 假设 | 优先寻找的正反证 | 可验证的改进候选 |
| --- | --- | --- |
| 局部完成替代最终结果 | 局部检查通过但用户原场景仍失败；对照完整验收链 | 从用户触发条件回推检查，比较是否减少同场景返工 |
| 纠正改变实现但未改变验收 | 实际修改后仍沿用原断言；对照新增能暴露原问题的验证 | 纠正时明确对象、范围、验收变化，检验下一次行动与验证是否同步 |
| 最新要求挤掉旧约束 | 新细节实现后撤销旧功能/断言；对照新旧约束同时满足 | 维护仍有效约束，检查是否降低约束丢失且不增加无效确认 |
| 任务对象或粒度误解造成返工 | 整体/单项、文字/布局等理解变化；对照正常细化 | 只在影响实现的歧义处核实对象，比较返工与用户确认负担 |

这些是研究假设，不能从历史关联直接断言根因。验证候选时使用同一任务初始状态和硬性验收，比较 baseline 与单一变化，保留正常迭代对照及未参与规则提炼的案例；按任务报告结果和未知状态。只有可复用的方法获得正反例支持后，才更新通用 skill；本轮数字与个案不写入通用规则。
