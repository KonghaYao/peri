# P1 issue 模板

写入 `spec/issues/YYYY-MM-DD-p1-<slug>.md`。只记录已确认事实；推断单独标注。

```markdown
# P1：<标题>

**状态**：已确认，待修复。
**优先级**：P1。
**类型**：<错误 / 回归 / 性能 / 可观测性 / 安全>
**创建日期**：YYYY-MM-DD。
**来源**：<用户报告 / 日志 / 测试 / 代码审计>。
**确认方式**：explorer 只读确认 + 主 agent 复核（基线 <commit sha>）。

## 确认证据

- <复现步骤，或代码路径，含 文件:行号>
- <日志/测试输出片段，已脱敏>

## 根因链

<触发条件 → 机制 → 用户可见后果；标注哪些是观察，哪些是推断>

## 影响面

- 用户影响：<>
- 受影响模块/调用点：<文件:行号>
- 是否可规避：<>

## 修复方案

- 范围：<>
- 明确不做：<>
- 回归测试：<测试文件与用例>

## 验收标准

1. <用户可观察行为>
2. <目标测试或检查命令>

## 验证记录

- `<命令>` → <结果>
```

## 填写要求

1. 证据必须可复核；不写"可能""大概"作为确认依据。
2. 行号以下单时的基线 commit 为准，commit 变化后重新核对。
3. 修复方案只覆盖本问题；相邻问题另开记录或写入最终汇报。
4. 验证记录在修复完成后回填，不用计划代替结果。
