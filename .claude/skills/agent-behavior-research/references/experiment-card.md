# 提示词实验卡

每条候选写一张卡。先填真实可用信息；无法还原的历史状态保留缺口，不用当前工作区冒充当时状态。

| 字段 | 要回答的问题 |
| --- | --- |
| ID、状态 | 是待复核的观察、prompt 候选，还是已执行实验？ |
| 焦点任务与机制 | 哪类目标在什么条件下出现了什么行为？ |
| 正例与反例 | 哪些 case/message ID 支持？相似任务中的成功路径或反证是什么？ |
| 替代解释 | 工具、运行时、数据缺口、任务难度或用户范围变化能否解释？ |
| 目标层与当前入口 | 应改变模型判断、工具契约还是执行系统？当前文件/符号在哪里？ |
| 最小 prompt 变化 | 修改哪一条决策规则，保留什么已有好行为？ |
| 初始状态与硬验收 | 任务输入、fixture/worktree、工具和可执行断言是什么？ |
| 版本身份 | baseline/candidate prompt hash、模型、工具、skill 和运行配置如何固定？ |
| 试验设计 | 同任务如何配对，重复几次，如何盲评/交换顺序，哪些任务是 held-out？ |
| 主要结果 | 按唯一任务列有据交付、部分交付、受阻、未知和约束回归；实际执行结果在哪里？ |
| 副作用 | 新规则是否导致多余澄清、重复验证、过度检查、越权或忽略取消？ |
| 采纳/撤回标准 | 哪些结果支持进一步试用，哪些明确反证要求撤回？ |

没有可执行重放环境时，先将机制改写为不含生产隐私的合成判例，只宣称校准了判据或局部策略。若评审规则与候选 prompt 同时改变，分别重评旧输出并运行新输出，否则无法区分 grader 改变与执行改变。

小型探索实验可以使用固定的少量重复并逐例展示结果；次数是预算选择，不代表已具统计功效。正式推广前按目标效果和任务变异规划样本量。多次调用、多个 judge 或同任务的多个片段不能当成独立任务扩大分母。

按实际实验链路区分决策输出、文件或参数编码、语法预检、真实执行和目标验收。任一层通过只支持该层结论；所有反馈修复轮都计入对应成本，不能只数语法错误而隐去格式修复。文件生成试验中的编码失败不能直接外推为原生工具调用协议失败。

冻结输入后若修改候选规则，保留原版本及其输出，给新版本另存 hash；旧试验不自动验收新版本。盲评存在合理分歧时，先保存独立标签与揭盲前的证据裁决，再汇总版本差异。无法确定必要性的澄清保留未知，不用多数票或揭盲后的偏好强判优劣。
