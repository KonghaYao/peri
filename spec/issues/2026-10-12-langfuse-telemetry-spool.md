# Peri 观测上报优化实施计划

> 日期：2026-10-12
> 状态：实施计划，尚未修改产品代码或执行性能验收。
> 范围：仅 Peri 客户端及其配置、资源适配、关闭生命周期；服务端继续使用现有 OTLP 接口。
> 源码基线：Peri `ad447afea63c5e6157e89e637c43022ed1828cf8`。实施前检查最新主分支差异。

## 1. 已确定的目标与边界

1. **磁盘暂存默认开启**：小包留内存，大包自动落盘；通过 `PERI_LANGFUSE_SPOOL_ENABLED=false` 关闭，关闭后使用有界内存路径。
2. **保留完整观测输入**：上报实际 LLM 请求的完整 input，不默认截断、摘要化或采样。现有显式采样配置继续有效。
3. **保持标准 OTLP/HTTP**：请求正文使用标准 gzip；本地队列中的文件引用只在 Peri 内部使用，服务端收到的仍是完整 OTLP 正文。
4. **复用 peri-fuse 已有 CAS**：本计划不新增服务端接口，不设计客户端与服务端之间的哈希协商、缺块补传或共享字典协议。
5. **控制遥测额外内存**：涵盖冻结输入、待落盘、待发送、编码及在途缓冲。业务会话、模型请求自身持有的上下文另行计量。
6. **磁盘能力遵守资源边界**：Agent/Harness 和 Controller 不直接依赖宿主文件路径或 `std::fs`；具体文件操作留在符合仓库边界的资源实现层。

磁盘暂存解决内存积压，gzip 减少网络字节，服务端 CAS 减少重复存储。每轮完整历史仍会重复传输；本计划不承诺消除随历史增长产生的累计传输量。

## 2. 已核实的当前实现

| 位置 | 当前行为 | 本次要解决的问题 |
| --- | --- | --- |
| `peri-controller/src/langfuse/tracer/generation.rs` | 活跃 generation 持有 `raw_body: Arc<Value>`，或 messages/tools；结束时形成完整 input | 大输入可能在长调用期间被遥测持续持有 |
| `langfuse-client/src/batcher/admission.rs` | 队列保存完整事件，按事件序列化字节及槽位准入 | 队列字节不等于实际堆内存，生产者和编码中的对象也未被统一覆盖 |
| `langfuse-client/src/batcher/worker.rs` | 内存聚合、FIFO flush 屏障、有界并发发送 | 引入落盘后必须保留屏障及唯一任务 owner |
| `langfuse-client/src/client_export.rs` | 预检、创建 OTLP 对象、编码到完整 `Vec<u8>` | 大对象、属性字符串和编码正文会阶段性重叠 |
| `langfuse-client/src/client.rs` | 未压缩 JSON POST；重试通过 `request.try_clone()` 复用请求 | 缺少 gzip；文件流请求需要重新打开正文 |
| `peri-config/src/observability.rs` | event 512 KiB、batch 4 MiB、queue 16 MiB、1024 槽、并发 2 | 512 KiB 会先于服务端 CAS 拒收；最终 OTLP 编码还有额外开销 |

现有 `flush` 等待前缀发送结果；`shutdown` 由部署 owner 关闭准入并 join worker。**“成功写盘”不能替代“发送成功”。**

## 3. 目标数据流与职责

### 3.1 两类引用，避免把大对象留到最后

| 内部对象 | 含义 | 生命周期 |
| --- | --- | --- |
| `InputSnapshot` | 已冻结的观测 input；小对象内存保存，大对象由资源层保存并返回不透明句柄 | 请求体到达至最终上报正文完成 |
| `ExportPayload` | 已封装完成、可重读的标准 OTLP 正文；含内容编码、压缩前后字节数和摘要 | 正文发布至发送终态及清理 |

以上是拟新增的内部概念，不是已有 API 或网络字段。具体类型命名可按代码组织调整。

1. 请求体到达时沿用现有映射语义冻结 input。大输入进入有界暂存任务，成功后替换遥测持有的 `Arc<Value>` 为快照句柄。
2. generation 结束后，结束事件保存小型元数据及 input 来源；落盘未结束时保存任务句柄，不另复制原文。
3. 发送准备阶段从来源读取内容，按现有字段映射生成完整 OTLP 请求，并直接写入 gzip writer。
4. 小正文保留受预算约束的内存字节；大正文生成已完成的暂存文件。发送队列只保存可重读 payload 及必要元数据。
5. HTTP 发送器流式读取正文；重试从头重开相同内容；完整成功后释放正文及不再使用的快照。

**快照提交成功且对应持有者释放后，才能减少遥测留存内存。** LLM/会话继续持有同一原始数据时，不能宣称该数据已从进程内存完全释放。

### 3.2 模块职责

| 层 | 责任 |
| --- | --- |
| `peri-config` | 解析 typed 配置、环境覆盖、默认值和合法性 |
| Controller/tracer | generation 身份、时间、输入快照归属、结束与取消；不执行文件 IO |
| `langfuse-client` | OTLP 映射、流式编码、大小判断、批处理、背压、HTTP 结果及重试策略 |
| 资源实现层 | 暂存对象写入/发布、可重读字节流、枚举恢复、独占领取、删除和配额 |
| 部署宿主 | 注入资源能力，保证发送器关闭后再关闭相关资源 |

资源接口只暴露实际需要的能力：创建临时对象、完成发布、取得长度并流式读取、分页枚举、独占领取、删除。不增加通用文件管理框架，不为遥测增加模型可调用工具。

复用现有资源装配与 MCP 部署方式。直接 IO 实现在仓库允许的资源边界内；若经远程资源传输，也必须有界分块，不能用一次返回全部内容的文本/base64 API 假装流式读取。

## 4. 配置与初始预算

**仅磁盘暂存默认开启及可由环境变量关闭是用户明确确定项；下面其余数值是实施起点和验收配置，需用测试校准，不是已测性能。**

### 4.1 对外开关

| 配置 | 初始行为 |
| --- | --- |
| `PERI_LANGFUSE_SPOOL_ENABLED` | 缺省 true；接受 `true/false`、`1/0`、`on/off`，忽略大小写及首尾空白 |
| `PERI_LANGFUSE_COMPRESSION` | 拟新增，缺省 `gzip`，可设 `none`；与磁盘开关独立 |
| settings | 增加对应 `langfuse.spool_enabled`、`langfuse.compression` 及预算字段 |
| 优先级 | 沿用环境值覆盖 settings，settings 覆盖默认值 |
| 配置来源 | 加入 `ENVIRONMENT_KEYS`，通过已有 configuration 数据面读取，不能另行直接读 OS 环境形成第二套权威 |
| 非法新配置 | 显式配置错误及既有装配诊断；不静默扩大内存或磁盘预算 |

关闭磁盘暂存后，不创建或恢复发送磁盘条目；已有文件不立即删除，下次开启时按过期规则处理。内存背压和 gzip 配置继续生效。Langfuse 未配置启用时，不创建暂存资源。

### 4.2 初始预算与语义

| 项目 | 建议起点 | 约束 |
| --- | --- | --- |
| 大 input 暂存阈值 | 序列化原文 256 KiB | 与网络最大请求大小分开 |
| 最终 payload 内存阈值 | 压缩后 256 KiB | 达阈值时把有界前缀转移至暂存对象，继续流式写入 |
| 遥测额外对象/缓冲预算 | 32 MiB/部署 | 统一跟踪等待落盘、编码、队列及发送；不等同于进程 RSS |
| 队列条目数 | 沿用 1024 | 文件引用也计数；恢复时分页，不将磁盘全部索引搬进内存 |
| HTTP 并发 | 沿用 2 | 所有发送均归现有 worker owner |
| 编码/落盘并发 | 初始 1 | 任务数、持有原文字节和输出字节均受预算控制 |
| 流式读写块 | 初始 64 KiB | gzip 内部状态、框架缓冲也计入测量 |
| 暂存总量 | 1 GiB/配置隔离域 | 包括写入中、input 快照、ready、sending 和待清理文件 |
| 待发送保留期限 | 24 小时，自首次接受起 | 重试不能重置期限 |
| 单次 HTTP 重试周期 | 沿用现有 60 秒累计期限及重试分类 | 周期结束可以持久保留待重试；不能把周期失败报为上报成功 |

预算先预留再持有新增遥测数据。不要通过无限 `spawn`、无界 channel 或等待磁盘的任务列表绕开预算。文件正文不按原文大小计入内存队列，但其索引、读写缓冲及准备中对象必须计费。

### 4.3 单条大小与拆批

1. 默认最终 OTLP **解压后请求上限暂保留 4 MiB**，另设线上的压缩体上限；两者独立计数。
2. 将默认单事件原文上限从 512 KiB 调整为最高 4 MiB，仍允许用户显式收紧。最终能否发送以 OTLP 编码后的实际大小为准，不能用原始事件大小代替。
3. 使用逐事件计量及有界事件来源拼接，尽量在构造最终 payload 前确定批次边界；最终 writer 再执行硬限额。超限时按事件边界拆批，重建未发送正文，清理失败的临时产物。
4. **单个 span 已超过最终请求上限时无法通过拆批解决。** 返回独立错误，计数并清理；不截断 input，不拆成服务端无法重组的多个伪 span。
5. 对已核实上限的 peri-fuse 部署，可显式提高客户端事件及请求限制。1000 轮完整历史是否能发送，取决于最终单条请求是否仍在双方限额内。
6. 关闭 spool 或资源不可用时仍受内存预算约束；允许较大逻辑事件不代表可以无限保留大对象。

## 5. 编码与 HTTP 契约

1. 使用现有 `POST /api/public/otel/v1/traces`、认证方式及 `x-langfuse-ingestion-version: 4`。
2. gzip 模式发送 `Content-Encoding: gzip`；保留 OTLP JSON 内容类型。文件长度可用于设置压缩后 `Content-Length`。
3. **流式写文件不够，字段转换也必须流式。** 现有 input/output 转为 OTLP 字符串属性的步骤不能先创建完整大字符串，再创建完整 OTLP 对象。为大 input/output 增加受限内存的序列化路径，保留 JSON 字符串转义与 UTF-8 正确性。
4. 验证对象、数组、引号、反斜杠、换行、多字节字符、嵌套工具参数与结果。对冻结 input 的基准序列化字节，与服务端解出 OTLP 属性后的字节做逐字节比较。
5. 这里的保真依据是 Peri 当前捕获并序列化的 input；不能声称恢复进入 `serde_json::Value` 之前原始 HTTP 文本的空白或键顺序。
6. 重试每次从头打开不可变 payload 并重建请求，保持 trace/span ID、时间及正文不变；不依赖克隆文件流请求。
7. 保留现有 429/502/503/504 与可恢复传输错误分类，复用 Retry-After、单调时钟、退避和 jitter。HTTP 客户端仍是响应和重试决策的唯一权威。
8. 保留 200 响应正文校验。部分拒收、无效响应和永久拒收沿用现有失败语义，不因落盘新增整批盲目重传。
9. 超时可能发生在服务端已接收之后，因此本方案不保证 exactly-once。相同 ID 便于关联，但不能替服务端承诺去重。

## 6. 文件与任务生命周期

| 状态 | 行为 | 异常后的处理 |
| --- | --- | --- |
| writing | 写临时对象，完成 gzip 收尾、长度及摘要后发布 | 未完成对象不能发送；取消、失败或恢复扫描时清理 |
| ready | 正文与小型描述信息完整、可重读，才算持久接受 | 独占领取后进入 sending |
| sending | 有界读取，维护同一 payload 的尝试状态 | 可恢复失败进入 retry_wait；进程崩溃后由恢复流程重新领取 |
| retry_wait | 持久保存首次时间、累计尝试、下一次允许发送时间 | 同一调度 owner 在到期后发起；超过保留期限后终结 |
| delivered | 收到完整成功响应，记录交付结果 | 释放关联引用并幂等删除正文 |
| terminal_failed | 超限、永久拒收、部分拒收、过期等终态 | 记录无正文的失败摘要后清理；不无限保留失败文件 |

### 6.1 发布与恢复

1. 正文和描述信息必须作为一个可恢复单元发布。文件后端可用临时目录及同文件系统原子重命名实现；需要崩溃持久性时执行相应同步操作。
2. 描述信息至少包括格式版本、内部 ID、事件数量、压缩前后大小、内容摘要、创建/到期时间、路由隔离指纹、重试状态。
3. 隔离指纹绑定规范化 endpoint 及项目凭据身份，不存储 secret。凭据或 endpoint 改变时，旧条目不能发送到新目的地。
4. 同一文件同一时刻只能被一个发送器持有；独占领取能力由资源实现提供，不能仅凭 PID 文件判断跨进程所有权。
5. 启动按固定页恢复索引，校验格式、长度、摘要、到期时间及隔离域。损坏条目记失败并清理，不发送不完整正文。
6. input 快照与最终 payload 的切换必须有明确所有权：只有最终正文发布成功后才释放其源快照；中断不同时丢失二者。
7. 快照尚未形成结束观测时，不合成新的“成功 generation”。废弃快照清理按原有取消/结束语义处理；遥测恢复不意味着恢复 Agent 执行。
8. 原生部署使用资源层的私有应用数据目录；文件权限限制给当前用户，不将认证信息写入正文描述或日志。

### 6.2 配额与降级

- 配额包含临时文件，预留输出空间后再写；失败后回收预留。
- 磁盘满、写失败、资源不可用：发出可见诊断，仅在内存预算允许时回落内存；否则按既有背压策略拒绝并计数。禁止无限内存回退。
- 生产默认沿用 DropNew，保护已经接受的数据。保留 DropOldest 的 FIFO 屏障约束，正在写入/发送的数据不能无所有权地删除。
- 小包内存路径在进程崩溃时仍可能丢失。只有完成持久发布的条目具有重启恢复资格。
- 平台只提供内存虚拟 FS 时，视为“未提供磁盘卸载能力”；不能报告 spool 已卸载内存。

## 7. Flush、关闭和恢复的语义

1. 保留当前 FIFO 前缀屏障；后续事件不能拖延已提交屏障。准备中的 input/payload 任务也必须归属于该前缀，不能绕过 flush。
2. `flush` 完整成功仍表示前缀条目完成现有 HTTP 成功校验。仅落盘、尚待发送或重试的条目不能返回成功。
3. 为磁盘保留路径增加明确的 Pending/Incomplete 结果，携带待发送数量及已持久化数量；调用方可区分“尚未送达但可恢复”和“已经丢弃”。
4. `shutdown` 先停止新准入，再在有界期限内等待准备、发送和清理；仍有可恢复条目时报告 PersistedPending，不能报告 Complete。
5. 不新增第二个独立后台发送器。Batcher 保持 worker/join 的唯一 owner，所有写盘及 HTTP 子任务均有可等待的归属。
6. 保留“取消 shutdown 等待不丢失 owner、后续可再次观察”的行为；发送资源比发送器晚关闭。
7. 一个重试周期失败后可以进入持久等待，但 flush/关闭必须如实报告失败或待发送。队列执行 HTTP 客户端给出的重试决定，不另写第二套状态码策略。
8. 新返回状态必须贯穿 SessionLike、部署关闭报告、ACP 宿主和测试；不能用 `Ok(())` 隐藏持久积压。

## 9. 验收场景与数字目标

以下均为待执行目标。先验证正确性，再评估压缩与 IO 开销；不得用截断 input 获得“性能提升”。

| 场景 | 配置/输入 | 通过标准 |
| --- | --- | --- |
| 默认及关闭 | 未设置开关；false/0/off；非法值 | 默认启用；关闭后新增磁盘文件数为 0；非法值可见；内存仍有界 |
| 内容保真 | 至少 100 个边界样本；中文、转义、数组、工具调用及大文本 | 解出的 input 字节与基准一致，0 mismatch；模型、usage、成本、ID 与时间字段不变 |
| 长会话 | 1000 次调用，最终 input 约 8 MiB；事件限额 12 MiB、最终解压请求限额 16 MiB；接收端确认支持 | 限额内的观测全部可查询，0 静默丢弃；逐条内容 hash 一致；记录总原文、总线包及 CPU |
| 编码膨胀 | 事件原文合计低于批次上限，但 OTLP 编码超过上限 | 自动拆成合法请求；可发送事件损失 0；没有整批误拒收 |
| 超大单条 | 单 span 编码后超过所配上限 | 精确拒绝该条并计数，同批其他条目继续；不截断或伪造分片 span |
| 慢网络/断网积压 | 512 MiB 压缩后待发送数据，spool 配额 1 GiB，HTTP 并发 2 | 遥测受控对象/缓冲目标不超过 32 MiB；不随磁盘积压线性增长；同机匹配基线的额外 RSS 峰值目标不超过 64 MiB，超出需解释分配器与平台缓冲 |
| 断网恢复 | 中断 10 分钟，未到 TTL 且配额充足，随后恢复网络 | 已持久接受且未终态拒收的条目最终送达；Pending 期间不报告 flush 成功 |
| 文件流重试 | 首次读到中途断连，第二次成功 | 第二次从字节 0 开始，完整正文摘要及观测 ID 不变 |
| 崩溃恢复 | writing、ready、sending、成功响应后清理前各注入崩溃 | ready/未确认发送文件可恢复；半写文件不发送；允许确认丢失导致重复请求，但不能丢失未过期已持久接受数据 |
| 配额及清理 | 小配额 8 MiB、TTL 60 秒、模拟磁盘满和删除失败 | 配额含临时数据；不出现无界内存回退；正常完成后正文引用和计费归零；失败清理可再次执行 |
| 生命周期 | 慢第一批、快第二批、并发新增事件、取消并重入 shutdown | 前缀屏障正确；唯一 join owner；所有状态及 Pending 计数准确 |
| 平台差异 | 原生持久化、关闭 spool、无持久化能力的 WASM 宿主 | 原生可卸载；其他路径报告真实模式、使用有界内存；内存 FS 不冒充磁盘卸载 |

性能评估另记录单事件冻结/入队耗时、gzip CPU 时间、磁盘写入量、P95/P99 发送延迟及最终排空时间。压缩率由真实语料决定，不预设“降低 80%/90%”作为已经成立的结果。

原生验收测量堆分配和 RSS；浏览器还需测宿主 JS/Blob/WASM 缓冲，因为 Rust 侧的流式接口不能证明宿主没有完整缓冲。
