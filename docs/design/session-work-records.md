# 会话工作记录

状态：已批准目标设计，首版代码已落地，准备合并。现行行为以代码与契约验证为准；实施进度及迁移窗口见 [实施任务](../../spec/issues/2026-10-06-workstate-redesign-implementation.md)，详细获批模型见 [设计契约](../../spec/issues/2026-10-06-workstate-redesign-proposal.md)。本文件只记录稳定目标，不宣称快速验收覆盖完整可靠性，最终效果由用户实测。

## 职责与数据权威

SessionResources 是消费 seam，SessionDataPort 的 SQLite/Turso adapter 提供同一领域保证。业务规则只维护一份，不把 SQL、事务或载荷回收机制暴露给 Agent。

- Mailbox 拥有原稿、投递、撤回与 Receive 领取。
- Processing 拥有本批输入、阶段游标与稳定累计预算。
- Effect 拥有调用意图、结果、任务绑定及精确委托关系。
- Transcript 是 canonical 内容权威；Control 是生命周期权威；稳定命令与回执负责幂等及 Unknown 对账。
- 请求、内容与结果按不可变引用保存于选定存储后端；不建立上层文件系统依赖或本地 fallback。

委托输入在 SDK 准入与 Receive 领取前，关联的 queued Delivery 暂存精确 DelegationRef。Claim 同事务将一致的委托引用转移到 Processing 并清除 Delivery 上的临时引用；领取后 Processing 是子侧关联权威，父侧 Effect 与绑定回执仍是关系证明，不复制完整任务绑定或提前生成执行身份。

新批次登记 SDK 关联时，AdmissionRecord 在同事务冻结初始候选的有界 Delivery 身份集合。Receive 按原票据与原成员领取，不因登记后的新投递重建候选或替换准入；后来的投递保留自己的待处理责任。既有 Processing 的恢复准入不重新领取初始批次，缺失初始成员证据也不从当前队列猜测。

## 性能与生命周期

普通状态转移只读取和更新本次关联记录；查询必须在存储层直接限量。历史内容不得参与普通状态更新的重新编码，禁止把分表记录重组成全会话聚合状态。

大载荷首次持久化、实际模型请求构造及显式历史加载有自身规模成本，不能以引用设计声称总成本为常数。未结算责任保留可恢复证据，容量满时明确拒绝，不通过丢消息或清原稿止血。

输入履行与后续阶段责任原子移交；模型响应与调用意图先可靠提交，才允许工具 dispatch。并发工具结果按调用身份结算，最后一项完成时只能发生一次阶段转移。Unknown 始终按原 mutation 查询或幂等重试，不因回执暂缺而判未执行。

会话 load 只恢复历史与冻结上下文，不复活旧执行。SDK 管理实例/attempt 唯一性，存储记录版本与 Control guard 不构成 Peri 执行租约或 owner fencing。任务/委托身份不随会话复用而复用。

## 切换边界

旧聚合运行实现删除，不兼容双写；存量仅经停写迁移一次性读取，无法证明的义务隔离并保留原证据，不作为新运行路径。迁移前备份及停止旧 writer 是部署职责；产生新格式责任后不允许只退二进制或恢复旧备份丢弃新责任。
