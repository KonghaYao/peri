# 消息区与覆盖层

按 [总目录](README.md) 的编号执行。用固定终端尺寸与长内容制造可重复的滚动位置。

1. **P0-28 长消息滚动不丢内容**
   1. 生成超过一屏的用户、助手、工具和子任务记录，滚到中部。
   2. 继续追加流式输出，再用滚轮、拖拽、端点点击及键盘浏览首尾。
   3. 核对阅读位置稳定、滚动条与内容同步，无白屏、跳行或重复条目。
2. **P0-29 主区与详情滚动条一致**
   1. 在同一尺寸下让主消息区和 subagent 详情都超过视口，记录主区位置。
   2. 打开详情，比较两处轨道与滑块，再滚动详情并关闭弹窗。
   3. 核对外观与命中方式一致、主区位置不变，最右列正文不被滚动条覆盖。
3. **P0-30 弹窗遮罩不穿透**
   1. 在消息区准备可点击工具卡、在输入框保留草稿，再打开面板和弹窗。
   2. 分别点击弹窗按钮、边缘及遮罩，按 Esc 逐层关闭。
   3. 核对仅最上层响应；工具卡、输入提交和底层面板不误触，草稿与焦点仍可用。
4. **P0-31 极窄终端仍可完成主路径**
   1. 把终端缩到约 40×8，启动一轮对话并打开面板或弹窗。
   2. 用键盘关闭覆盖层、继续提交，再放大终端。
   3. 核对小尺寸下输入、状态与回复仍可读且能提交；放大后不白屏、不残留遮罩或丢失正文。
5. **P0-83 History V2 唯一链路与失效恢复**
   1. 用本地 SQLite 后端启动 TUI 并打开历史长于首屏的会话，确认首屏来自 `session/load` 的
      initial，后续只出现 `_peri/history` 的 page/seek/body，没有旧分页、旧窗口或旧提交通知的
      消费痕迹。
   2. 滚到顶端加载更早一页，再滚到底部检查 after 方向；核对条目无重复、顺序稳定，旧阅读位置
      不被迟到页改写。借助缺口定位或测试注入的跳转锚点执行 seek，确认旧位置被新页替换。
   3. 打开超大/opaque 条目的占位 note，确认详情按 `body` 分块读取、首块后按 body 的
      `totalBytes` 修正滚动范围，首屏与详情都不内联完整 JSON；同代次 before/after 翻页保持
      详情，seek 或窗口重开使旧 window/snapshot 失效时详情自动收起。
   4. 让服务端窗口过期/关闭，确认旧页仍可读并显示失效提示；继续滚动或重新打开后新窗口替换
      旧窗口，无两套游标混用。服务端返回操作进行中时，确认客户端不重复发起同一操作。慢
      body 读取期间按 Esc 取消或关闭会话，确认 cancel/close 及时响应，迟到结果不写入界面。
   5. 连接一个未选择 History V2 的服务端，确认 TUI 启动即显式失败，不显示旧协议历史，也不
      回退标准全量回放。
