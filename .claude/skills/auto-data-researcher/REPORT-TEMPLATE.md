# 研究报告骨架：结果与重要等级在前

这是阅读顺序，不是研究执行顺序。按规模裁剪章节，但所有发现步骤、验证记录与交付清单必须在结果及行动建议之后。未测量项填“不可用”及原因，不填零。

## 1. 结果摘要

用 1–3 条直接回答：最重要的问题是什么、影响什么、建议先做什么。不以研究范围、工具使用、测试通过或文件路径开场。

## 2. 按重要等级排列的发现

等级定义见 SKILL.md“报告与最终汇报”。P0 / P1 / P2 表达重要性，`observed` / `candidate` / `unverified` 表达证据状态，两者分开标注；没有 P0 就不设 P0 章节。

每项使用以下结构，不按发现时间排序：

### [P1] 直接表达问题的标题 · [observed / candidate / unverified] · [稳定 ID]

1. **结果**：一句话判断，附最关键的观测值与分母；无法量化则说明。
2. **影响与定级理由**：为什么值得优先处理，影响的对象和边界是什么。
3. **建议行动**：修复还是先验证，什么可观察结果才算改进。
4. **必要限定**：影响该项解释的未知、反例或范围限制紧跟结论；不能只藏在附录。完整证据用稳定 ID 关联后文，不在这里展开取证流水账。

## 3. 建议行动顺序

以有序列表说明先做什么、后做什么及原因。区分研究方法改进与产品修复，不把未获授权的修复写成已实施；避免重复整段发现。

## 附录 A. 发现过程、来源与口径

- 来源、读取方式、运行时间、schema/解析器/规则版本；原始路径仅按需本机保留。
- 快照或指纹及覆盖对象；过滤条件、时区、半开边界和时间字段。
- 总体、单位、指标分子/分母、阈值、去重/配对身份、未知状态和排除依据。
- 抽样候选集、选择方法、seed、实际阅读量、唯一会话数及跨标签重叠。
- Agent 失败模式研究另列超长对话、`ultracode`、`multitask` 等层的识别证据、覆盖/缺层和顺利对照；附目标修订、压缩/交接、派发回收与验收转折点走查，按长流程审计指南保留完整身份和缺口。
- 解析失败、缺失、冲突、孤立记录、继承/双写和来源污染；对账差额与敏感性比较。
- 每项发现的完整源 ID、安全摘要、上下文范围、反例及撤回记录；不保存无关原始对话或工具参数全文。

## 附录 B. 验证、复现与局限

- 可重复命令、机器产物、实际退出状态、有效用例或样本数量。
- 区分计算正确性、案例复核、代码验证、实际行为变化与因果效果，不以单项通过代替全部验证。
- 逐条核验报告与队列引用的存在、所属来源和语义支持；说明未验证项及缺失观测。
- 比较时列出两侧样本量、分母、缺失能力与不可比项；方法变化须重新生成受影响产物。
