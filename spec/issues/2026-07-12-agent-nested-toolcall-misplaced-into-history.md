# Agent 工具调用内部的子工具调用跑到历史消息区，未嵌套在 Agent 卡片下方

**状态**：Open
**优先级**：中
**创建日期**：2026-07-12

## 问题描述

主 agent 调用 Agent 工具（同步 SubAgent 调用）时，子 agent 在内部执行的工具调用（Grep/Read/Bash 等）卡片应该作为 Agent 卡片的嵌套子元素，渲染在 Agent 卡片下方（缩进/边界标识表明归属）。但当前这些子工具调用卡片被错误地渲染到了 Agent 卡片**上方**的历史消息区——看起来像是「先于 Agent 发生」或「属于更早的消息」，与实际执行顺序和归属都不一致。

所有 Agent 工具调用都必现此问题。

## 症状详情

| 维度 | 当前行为 | 期望行为 |
|------|----------|----------|
| 子工具卡片位置 | 渲染在 Agent 卡片**上方**，混入历史消息区 | 嵌套在 Agent 卡片内部/下方，作为 Agent 的子元素 |
| 子工具卡片归属 | 看起来像「先于 Agent 发生」或属于更早的消息 | 明确归属于它所在的 Agent 卡片（缩进/边界） |
| 子工具卡片可见性 | 已经渲染出来（不是丢失） | 仍然渲染，但位置正确 |
| 触发范围 | 所有 Agent 工具调用必现 | — |

典型影响：用户无法从 UI 上判断「这个工具调用是哪个 Agent 派生的」，嵌套层级关系完全错乱，与 Claude Code 中 Agent 展开后子工具缩进嵌套的展示效果不一致。

## 复现条件

- **复现频率**：必现
- **触发步骤**：
  1. 启动 Peri TUI，发起一段会话（产生若干轮历史消息）
  2. 在新一轮交互中，主 agent 决定调用 Agent 工具（如派发一个 SubAgent 搜索/探索）
  3. SubAgent 在内部执行若干工具调用（Grep、Read、Bash 等）
  4. 观察这些子工具调用卡片的渲染位置——它们没有出现在 Agent 卡片下方，而是向上飘到了历史消息区
- **环境**：TUI 前端，所有 Agent 工具调用均会出现

## 涉及文件

- `peri-tui/src/kit/message_area/render.rs` —— Agent（SubAgent）卡片及其嵌套工具调用的渲染逻辑所在，决定子工具卡片相对 Agent 卡片的位置
- `peri-tui/src/kit/acp_events.rs` —— Agent 工具调用相关事件 → `VIEW_MODELS` 的写入顺序（事件时序决定卡片在 `items` 中的最终位置）
- `peri-tui/src/kit/acp_bridge.rs` —— Agent 状态 → Atom 的桥接（SubAgent 内部工具事件如何归属到父 Agent）
