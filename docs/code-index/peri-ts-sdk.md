# Peri TS SDK 代码索引

唤醒合并回归：`src/execution/coordinator.ts::ensureProcessing` 为同会话 active operation 保留 dirty wake，旧查询返回 idle 时继续检查新工作；单执行、Unknown、退役与 drain 上界保持。`test/execution-wake.test.ts` 用屏障覆盖重叠 notification、Stop/Resume、预算与封闭边界。`execution/sqlite-busy.ts` 将 registry/admission ledger 的运行期 busy 等待改为有界异步退避，仅在写事务 callback 尚未开始时重试获取锁；callback/commit 后失败保留 Unknown/原错误，不重放。`test/execution-sqlite-busy.test.ts` 覆盖独立 writer、事件循环让出、deadline、关闭与禁止不安全重试。连接级 pragma 不改变 schema；构造期初始化、SQL/JSON/落盘仍同步，不承诺事件循环完全无阻塞。

Cloudflare 网页聊天消费端：[`peri-cf`](peri-cf.md)，使用 SDK 的既有 WASM transport；应用内 facade 接入工作区可移植模块，不增加 SDK public entry、package exports 或构建目标。`execution/admission-core.ts` 是 SQLite 与 DO registry/ledger 共用的唯一执行准入规则及 async ledger 契约，`admission-service.ts` 保留原本机 SQLite API 和装配。这是本应用保留的两处 SDK 源码改动，目的是隔离 `bun:sqlite`，不在应用复制准入规则。浏览器 WASM 入口不引入 Node/Bun 依赖，Worker 的 `node:crypto` 由 `nodejs_compat` 提供；可移植性与官方 driver 实际执行测试位于 `peri-cf/tests/`。

Workers 消费端通过应用 facade 接入原有 `TursoStorage`，显式传入凭证，直接查询 Rust Store 会话元数据，复用未改动的 `storage/session-summary.ts` SQL 与映射；不创建 DO 会话目录，也不维护应用自己的会话表。元数据写入仍由 Peri 的 ACP 生命周期管理。

状态：SDK 的 stdio/WASM transport 共用 ACP；`SessionDocs` 只投影展示状态。RCRA 执行准入的单一权威为 SDK 持久 ExecutionRegistry，Rust Store 持有消息、工作义务、领域控制、处理阶段、invocation 与资源 owner 声明及回执；Rust 不建立执行 owner/lease/fencing。协议版本 `peri.executionProtocol=1` 已接入 SDK Session、反向准入和 Bun JSONL dispatcher。生产路径与验收结果必须分别核对：完整 native/WASM、冷 child runtime 和分布式 owner 恢复以 active spec 及对应真实生命周期测试为准，不从 SQL/JSONL fixture 推导全部 E2E 已完成。权威语义见 [RCRA 设计](../design/rcra-message-activation.md)，部署接口见 [SDK README](../../npm-packages/@peri-sdk/README.md)。

协调域契约：共享 `AtomicManagedAgentKv` keyspace 覆盖可能执行同一 Session 的全部实例；Session key 不含 `Sandbox.id`。不同数据库相同 ID 共用 KV 时保守拒绝，可按业务隔离 KV，不能通过不同 Sandbox 绕过同 Session claim。`Sandbox.id` 仅用于 Agent key，不是 Peri `machine_id`，SDK 不将其注入 Peri；机器归属校验、并发 claim 与 ExecutionRegistry 准入互不替代。claim 过期、旧 socket 不可连接和 TTL 均不是停止证明；跨实例替换必须先得到旧 exact generation 的可信 stopped proof。

清理实现：`src/agent/session.ts::startOnce` 启动失败且清理未确认时保留 `cleanup-pending`、claims 与 transport，以 `AggregateError` 同时报告原错误和清理错误；`close` 共享清理事务，失败后可重试，`cleanupExecution` 确认 transport 清理后才按 owner 释放 claims。`src/transport/json-rpc-transport.ts::close` 在 wire 清理失败后允许重试，不重新开放 ACP 准入。

恢复与 RPO：默认 Session/sidecar 的 SDK ledger 位于 `~/.peri/execution/registry.db`，SQLite 使用 WAL、FULL synchronous 和同一事务提交 record 与 mutation receipt；SQL metadata / KV envelope 的 SDK 协议版本为 1，不是 Rust Session Store schema 版本。已确认 durable receipt 的恢复依赖后端兑现持久提交承诺；未确认的写入只能 resolve 原命令，不能推导零丢失或执行成功。Memory 的 bestEffort 声明不提供崩溃 RPO。Rust Store 与 SDK ledger 不共享分布式事务，须分别恢复 work/control/processing/checkpoint/invocation/owner 声明与 instance/attempt/budget/receipt，再通过原 WorkCommand、原 ticket 和 Store entry ACK 收敛；不可从 transcript 重造义务、重新 mint 命令或重置同 work 预算。

恢复步骤：读取版本及稳定回执 → 确认原 instance 已持久 Stopped 或取得真实停止证明 → 注册新 generation → resolve 原 pendingCommands/entering ticket → 重读权威 work/control → CAS 准入。未知 proof、缺失 child runtime 或可信 owner route 必须 Blocked/Incomplete。正常 Close 另须先确认领域 Closed+settled，再 seal dispatcher、停止 transport、join owned calls、核验停止证据并记录 Stopped；Bun 宿主仍活不妨碍已退休的 owned generation 完成，但旧 actor 不得继续执行。

超 RPO 回退：`peri/execution/entered` 的 Store 提交 ACK 将 `enteredEvidenceId` 持久写入 SDK attempt。Running/Exiting 或仍保有 entered evidence 的已结清/历史 attempt，若 cold domain resolve 原 ticket 返回 NotApplied，coordinator 记录永久 `disaster:{kind:dataLoss,reason:enteredAdmissionMissing,ticket,enteredEvidenceId}`。`ensureProcessing` 返回 typed disaster；send 暴露 `ExecutionDataLossError`。保留原 entered/stopped proof 与预算，拒绝重新注册/准入，不当作 NeverEntered，不因 Resume、重启或 scan 消失。反向 admit 保留 Blocked wire 并附 typed disaster；真正未收到 entry ACK 的 entering 才可按原 NotApplied 安全封存。新 generation 替换及 child/sidecar 准入也复用 coordinator 的历史证据核验。

验证边界：`test/execution-{registry,session,sidecar,jsonl-duplex,turso,disaster}.test.ts` 覆盖真实 SQLite、子进程退出、JSONL、本机 loopback sqld 的官方 Turso driver 事务契约及 SQLite domain receipt fixture 的备份回退。loopback SQL fixture 不是生产网络故障、跨 host owner 恢复或分布式 RPO proof；Turso/external 需部署方提供真实 InstanceProofProvider。`tests/real-peri-disaster.test.ts` 使用实际 Peri Store、实际 entered ACK、SIGKILL 后 sealed/joined dispatcher 的精确停止证明和真实 domain SQLite 旧备份恢复，核验 DataLoss 后不再调用模型或重置预算。`tests/real-peri.test.ts` 与 WASM integration 另覆盖实际控制/输入路径，必须使用当前源码构建的 binary/WASM，不以旧产物通过替代协议变更验收。

实时投影边界：`task-projection.ts` 将缺少本次 started 证据的后台非终态快照标为 `unobserved:<原状态>`，保留历史事实但不宣称当前运行；终态事实与真实 started 驱动的活动仍投影，失去观察后仅靠 running 快照不能复活活动。回归见 `tests/task-snapshot-activity.test.ts`。Peri 的 `session/load` 历史逐条回放若中途发送失败，Host 当前只记录告警后仍返回成功；SDK 尚不能证明回放完整。长期会话反复 compact/rewind 会在同一 Y.Doc 内产生删除记录；当前保持根集合对象身份以供订阅者使用，尚无 Fenix Doc Hub 式文档换代与快照压缩协议。
