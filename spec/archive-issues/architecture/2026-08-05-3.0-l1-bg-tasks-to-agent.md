# L1：BackgroundTaskRegistry 与 bg shell 执行迁至 Agent 层（per-session 实例化）

**状态**：Fixed
**标签**：`3.0-refactor`、`agent-layer`
**优先级**：高
**类型**：重构
**创建日期**：2026-08-05
**来源**：`spec/issues/2026-08-05-peri-3.0-refactor-prd.md`（伞形 PRD）决策 3/4

## Problem Statement

`BackgroundTaskRegistry` 目前是进程级全局单例且只有单 session 槽位（`peri-middlewares/src/subagent/background.rs:135`），bg shell 与 bg fork 任务的管理权握在 Middleware 层。多会话场景下任务互相干扰；任务生命周期（取消/事件/超时）不跟随 session，违反 §0「生命周期：状态跟着 session 活的归 Agent」与 §2「async tasks manager / BackgroundTaskRegistry 归 Agent 层统一管理，per-session 实例化」。

## Solution

将 registry 的定义与实现迁入 peri-agent，改为 per-session 实例化：随 session 创建/销毁（生命周期/取消/事件跟随 session）。Middleware 只保留任务定义与启动发起（调 Agent 层 TaskManager 接口），不再持有管理权。bg shell 的实际执行（进程 spawn/进程组/超时/输出收集）归 Agent 层 async tasks manager。Task 保持易失投影语义：不持久化，重启不复活，遗留 Running/Creating 记录标记为中断。

## 验收标准

- [x] `BackgroundTaskRegistry` 定义与实现位于 peri-agent，per-session 实例化（随 session 创建/销毁）。
- [x] Middleware 侧不再持有 registry，仅经 TaskManager 接口发起任务（任务定义 + 启动发起）。
- [x] bg shell 执行（进程 spawn/进程组/超时/输出收集）在 Agent 层完成。
- [x] 任务取消、超时、完成事件均跟随 session 生命周期，多会话并行不互相干扰。
- [x] 单元测试随迁（`peri-middlewares/src/subagent/background_test.rs` 语义保持），并补充 per-session 实例化与销毁用例。
- [x] 现有 `2026-08-05-bg-*` 系列 bug issue（bg-cancel-abort-skips-cleanup、bg-shell-task-id-collision、bg-task-over-limit-still-runs 等）复验通过或更新。

## 非目标

- 不改变 bg 任务的业务语义（执行/输出收集行为不变）。
- 不实现任务持久化（Task 为易失投影，属设计契约而非本子 issue 目标）。
