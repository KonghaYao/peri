# 验证报告 1：SDK Yjs 展示存储与通信基线

状态：独立验证完成；仅审查代码、原始数据及来源，不重复执行压力场景。验证对象为 [计划](00_plan.md)、[实验报告](01_experiment_report.md)、[原始结果](raw/baseline/summary.json) 与 [来源记录](raw/baseline/provenance.json)。本报告不替代候选实现的行为验收。

## 总体评估

**PARTIAL**。第一轮数值、完成状态及限定范围内的结论可信，可以作为第二轮基线。没有发现结果矛盾、预算截断或伪造的通过状态。仍需加强候选视图的语义校验、统一异步通信计时口径，并补齐从干净环境重建基线的步骤；否则第二轮可能在减少实际工作量或移出计时区间后获得失真的改善比例。

## 逐维度评估

### 数据完整性：PASS

- 逐项比较 12 个场景 JSON 与 `summary.json`，内容全部一致；4 个场景各有 3 个独立进程样本，均为 `status=passed`、子进程 `exitCode=0`、`reason=null`，对应进度日志也有成功终态。没有以命令启动代替完成证据。
- 12k 工具的 3 个样本均逐个核对了 12,000 条参数、结果及工具终态，原始参数和结果均为 111,050,670 bytes。大结果场景均核对 1 条完整工具结果，原始载荷 1,049,635 bytes。
- 视图样本均保留 128 个原始延迟、128 次发布、128 KiB 尾部文本精确校验；独立重算总和、数组上中位数和 nearest-rank p95，均匹配 JSON。这里的 p95 是单个进程内该连续工作负载的经验分位数，不能当作生产请求延迟分布。
- 三个 stream 样本均完成 16,384 个分片，全文 16,777,216 bytes，实际和预期 SHA-256 相同；接收文档终态为 `completed`。每次均为 16,389 帧、25,189,286 JSON body bytes、17,703,875 decoded V1 update bytes。
- 独立重算报告列出的均值、中位数与样本标准差，全部匹配报告精度。例如工具投影均值 1,866.971942 ms、标准差 53.457707 ms；128 次视图总耗时均值 3,048.263002 ms、标准差 37.111118 ms。
- 全部样本的终态耗时和进程峰值 RSS 都低于 120 秒、2 GiB 限制。短场景的外部轮询 RSS 为 0，表示 250 ms 轮询未捕获到进程，并非零内存；报告实际采用的进程峰值均非零。

### 方法正确性：PARTIAL

确定性生成器、每个场景独立进程、三个样本以及串行执行符合本轮目标。计时排除了工具载荷生成与 JSON 字节统计；工具批次从首批约 25–27 ms 增长到末批约 293–324 ms，与冻结基线 `ChatProjection.acceptTool` 每次遍历 entries 的代码一致。冻结 `readSessionView` 的确会全量读取消息并递归复制工具对象，因此报告关于当前行为的解释有代码支持。

以下限制必须进入第二轮设计：

1. `viewScenario` 仅核对新增尾部文本、发布数及首个工具的对象身份，没有断言全部历史工具仍出现在视图中。`firstTool` 可能返回 `null`；若候选丢掉工具块，`null === null` 仍可计为身份复用。基线的 0 次复用并未因此失效，但候选需断言首个工具非空、工具数量与归属正确、旧历史内容保持完整，并对真实工具更新验证缓存失效。
2. `toolsScenario` 验证工具状态，但仅记录会话 `activeTurnStatus`，没有把非 `completed` 当作失败。当前 6 个 tools/large 样本实际均为 `completed`，故报告观察成立；第二轮需把该终态加入断言。
3. 基线 stream 的 `projectionMs` 包含同步帧处理和远端 apply；改成异步批处理后，单次 `accept` 耗时会排除延后的工作。比较时必须另计最终 flush 后的端到端完结时间，或保证两边覆盖同一执行边界。
4. 3 个进程样本足以描述本机大幅差异，不足以证明小幅收益或统计显著性。stream 的同步紧循环不会触发真实模型输出节奏下的定时刷新；该场景的帧数不能外推到任意消息到达间隔。

### 结论合理性：PASS

报告区分了观察和推断，并将结论限于 SDK 投影、读取和 demo 桥接。约 116 MB 的双文档冷快照与约 111 MB 原始载荷之比、未变工具 0 次身份复用、1 MiB 大结果几乎全部进入冷快照，都有直接数据支持。

报告没有将 1.29–1.41 GiB 的完整进程峰值解释为单个常驻文档内存，也没有将进程内 JSON/base64 帧字节解释为 HTTP/SSE/TCP 流量或生产网络吞吐。对 16 MiB 文本未观察到严重追加瓶颈的表述准确：这只支持当前连续追加场景，不能证明带长历史、交错更新、浏览器渲染或多消费者时仍有相同表现。

基线不支持状态向量恢复、慢消费者限额及版本化载荷读取，报告明确标为不适用。重复/乱序更新的 Yjs 原语性质也未被误写成 demo 应用层契约已通过。取消、回放、compact/rewind、切换与销毁仍须在候选契约测试中验证。

### 可复现性：PARTIAL

- 重新计算冻结 `src` 指纹、demo bridge 指纹及四个 benchmark 文件指纹，均与来源记录匹配。再与提交 `567640f1837771442628970a56ce68c5a8f8e256` 逐文件比较，冻结目录中核对的 42 个文件全部一致；提交里的 `bun.lock` 未复制到冻结目录。
- 环境记录包含 Bun 1.4.2、Yjs 13.6.33、CPU、系统版本和内存。指定 Bun 绝对路径解决了本次 shell 版本歧义；后续采样仍应验证实际版本，并记录依赖锁文件或安装指纹。
- 当前复现命令依赖已存在的 `/tmp/peri-yjs-sdk-baseline-…` 和链接到工作区的 `node_modules`。临时目录清理或依赖变更后，命令不能单独重建实验。应补充从指定提交导出 SDK 源码、demo bridge、package/锁文件及安装固定依赖的步骤，并保存本轮 harness 的可检索版本。来源指纹可用于检查一致性，但不能重建文件内容。
- 原始输出目录写错后被移动的事实已披露；JSON 与汇总一致，保留的日志旧路径与说明一致，没有发现此操作改变测量值。

### 报告质量：PASS

环境、假设、方法、样本表、统计、观察、推断及限制齐全，原始数据可以追溯。工具与流式工作量、快照编码版本、JSON 与 decoded update 的区别、初始快照是否计入增量数字都说明清楚。Yjs 随机 clientID 带来的变长编码差异已披露；工具快照样本的轻微字节差异没有被误当作工作量变化。

## 第二轮必须控制的变量

| 变量 | 比较要求 |
| --- | --- |
| 数据生成器 | 保持 workload version、12,000 工具、每 10 工具一个 assistant、输入/输出结构、状态更新次数与 16,384 × 1 KiB 分片相同；更改生成器须另列场景。 |
| 语义工作量 | 验证公开视图中的工具数量、顺序和归属，以及完整输入/结果按需可读；不能把缺失历史、截断全文或省略终态计为优化。 |
| 热文档与外置载荷 | 分别记录热快照、载荷存储、按需读取字节；快照变小不能自动推出总存储变小。冷接收端必须通过受测读取路径取得精确全文。 |
| 缓存正确性 | 未变工具保留身份；已变工具刷新；先前发布快照保持原值；replaceDocs/destroy 后旧文档不得继续发布。 |
| 编码及载荷阈值 | 明确 V1/V2、二进制 envelope 与 JSON/base64 的字节口径，以及 inline/preview 阈值；整体方案收益与单个因素收益分开表述。 |
| 刷新策略与计时 | 记录时间间隔、字节阈值、实际 flush 数和完成 flush；同时保留同步提交时间、apply 时间及接收端完成时间。 |
| 到达节奏 | 原有同步紧循环和 128 次微任务发布场景保持不变；如声称定时批处理在异步流有效，另加明确节奏的场景。 |
| 运行环境 | 固定 Bun/Yjs 与依赖，使用独立进程、同一机器和资源预算，串行采样；记录源指纹。小幅差异若需归因，增加交错采样以降低温度、负载与执行顺序影响。 |
| 内存统计 | 保留整个场景进程峰值与阶段说明；接收文档、编码缓冲、载荷存储及校验过程不能在两边悄悄增减。 |
| 生命周期 | 恢复、重复/乱序、慢消费者、取消、回放、compact/rewind 和文档切换分别由行为测试证明，不能只靠吞吐场景推断。 |

进入候选实验前，补上视图历史完整性和会话终态断言，明确异步 flush 的计时边界；复现说明补齐基线重建与锁定依赖。第二轮同时保留完整语义校验与本轮原始数据，可继续实验，无需为本轮已有可信观察重跑压力场景。
