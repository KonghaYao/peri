### 🔴 P0-2：后台任务默认 15s 超时语义矛盾——2/5 会话，工具层新发现

**本轮新发现**（上轮是轮询成瘾，这轮是超时语义本身反直觉）：

- 019fbdbe：[#59] 后台 3 分钟监控实验被 15s 默认超时静默杀掉；[#177] **已知 15s 限制后仍未传 timeout**，后台 npm test 又被杀——子进程孤儿存活跑完了测试，通知却误报"失败"（[#181]），agent 靠读日志才发现实际通过；[#165] 前台 600s 超时，进程树被杀、输出全丢，靠 ps/tmux ls 拼状态，测试全部白跑
- 019fc204：[#150] run_in_background=true 未设 timeout → [#157] 15s 被杀 → [#158] 前台重跑成功（19.8s），agent 自述"我忘了设 timeout"

**根因**：`run_in_background` 仍受默认 15s 超时约束（设计意图矛盾）；超时只杀 wrapper 不杀进程组（孤儿进程存活、通知语义错乱）。

**修复方向**：① 后台任务默认不超时或给长默认值，超时需显式传入；② 超时 kill 整个进程组，通知区分"wrapper 被杀 / 子进程可能存活"；③ 前台命令超时后提供"转后台续跑"恢复路径，避免输出全部丢失。
