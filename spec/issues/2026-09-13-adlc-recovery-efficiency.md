依据：[长对话审计](../../side-projects/agent-defect-analyzer/reports/2026-09-13-adlc-bottlenecks/README.md)。历史样本用于定位机制，不作为已测量的收益基线；现行代码优先。Workflow 脚本说明已在 `0c5aa9a3` 修正。

## 验收范围

1. 真实 Workflow 结果验证路径接受合法整数 revision，拒绝小数；相关嵌套、数组、required 与既有合法输出有回归证据。
2. ADLC 使用可复用且有上限的文件边界检查；缺失或错配基线先失败；ignored 写入、范围外变化仍可见，覆盖不足不得判定通过。
3. 区分产品缺口、能力不可用、协议无效、收尾失败。恢复前核对契约、源码、依赖和证据身份，保留有效结果，只安排受影响工作；评估独立性不变。
4. 按实际工作包安排预算和恢复交接；依赖验证未通过时不启动下游；超时或取消不等于完成。
5. 既有且未变化的 dirty 不归责本任务；范围外变化的责任未知时保留未知，不能自动豁免或掩盖独立验收缺口。
6. ADLC 按阶段必需产物检查业务结果。缺交付的空运行给出恢复原因；通用纯 JS 与有效缓存恢复允许零次新 Agent 调用。

## 边界与验证

保留两个逻辑 Workflow、引擎终态与产品验收分离、既有取消和审批边界。支持代码必须能随实际运行时取得，不能只在仓库中放置运行时无法加载的脚本。根 Agent 编写 skill，Luna 执行代码模块与回归测试。

从真实结果验证器与临时仓库 fixture 开始；测试有界扫描、失配与越权、四类恢复、产物缺失和缓存恢复。提交仅包括本任务路径或 hunk；部分暂存后的代码快照在隔离目录验证。完成时更新单一事实源与分析成果映射，删除本实施记录，历史保留在 Git。
