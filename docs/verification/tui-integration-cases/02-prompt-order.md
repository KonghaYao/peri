# 输入与消息时序

按 [总目录](README.md) 的编号执行。需要可控模型响应时，分别给每轮输入和输出使用不同标记。

1. **P0-06 单轮提交只产生一次请求**
   1. 在空闲输入区输入唯一文本并按 Enter，等待模型回复与终态。
   2. 核对输入框清空、用户气泡后出现独有回复、模型端只收到一次请求。
   3. 确认 loading 消失，再按 Enter；刚才的文本不得被重复发送。
2. **P0-07 新 prompt 跟在旧回答后**
   1. 让首轮助手文本已显示，但暂缓旧回合终态。
   2. 提交第二条 prompt，立即检查首轮用户、首轮助手、第二轮用户的顺序。
   3. 释放终态并等两轮结束；顺序仍相同，新气泡不合并、不上移到旧回答之前。
3. **P0-08 运行中多条排队按序发送**
   1. 保持首轮模型请求未完成，连续提交带不同标记的第二、第三条输入。
   2. 检查待发送数量和顺序，再依次释放模型响应。
   3. 核对模型端按提交顺序收到请求；每条输入只显示一次，回复分别归属对应输入。
4. **P0-09 队列投递只显示一次**
   1. 对同一 canonical input ID 重复投递，并插入旧 generation 的迟到通知。
   2. 检查 TUI 只新增一个用户气泡，模型端只执行一次，旧通知不改变屏幕。
   3. 再投递新的 input ID；新气泡应正常出现，不能被去重误吞。
5. **P0-10 旧终态不结束新回合**
   1. 在首轮终态可能迟到时启动第二轮，并让第二轮先显示部分回答。
   2. 送达旧请求的 TurnDone 或 TurnInterrupted，观察第二轮状态。
   3. 核对第二轮继续 loading、气泡和回复未被清除；只有第二轮终态使界面回到空闲。
6. **P0-11 零产出取消恢复输入**
   1. 提交独有文本，在任何助手内容出现前取消当前运行。
   2. 等待匹配终态；确认输入框恢复原文、未完成气泡消失、loading 结束。
   3. 再提交恢复文本；只产生一条新请求，不重放已取消请求。
7. **P0-12 重放完成后再提交**
   1. 触发 compact 后的会话重放，在重放与新提交相邻时输入新 prompt。
   2. 等待重放与新回复完成，核对历史只出现一次且位于新输入之前。
   3. 检查新请求绑定重放后的会话；旧缓存和旧终态不能改变新气泡顺序。

## P1 补充场景

1. **P1-01 Stop 后直接提交能启动新任务**（[issue](../../../spec/issues/2026-10-07-stop-resubmit-queue-defect-p1.md)）
   1. 在流式运行中 Stop，分别于收尾前后立即输入新文本并按 Enter。
   2. 等待新回复，检查新输入未永久停在待发送区且只执行一次。
   3. 核对 Stop 前已排队的旧输入不因此自动发布，恢复授权只兑现当前新提交。
2. **P1-02 Enter 后及时给出真实反馈**（[issue](../../../spec/issues/2026-10-07-p1-tui-enter-message-latency.md)）
   1. 在空闲、首次建会话、忙时排队和长历史四种负载下分别提交唯一文本。
   2. 记录按键至用户可见反馈、正式投递及模型请求的关联时间。
   3. 核对提交不丢失或重复；待发送与已投递状态明确区分，延迟有可复核测量。

## P2 补充场景

1. **P2-01 长中文待发送项点击发送**（[issue](../../../spec/issues/2026-10-08-p2-tui-pending-send-click.md)）
   1. 保持旧回复流式输出，准备一条长中文待发送项与另一条草稿。
   2. 单击可见发送图标，再改变终端尺寸重复同样操作。
   3. 核对旧流被中断、所选输入只投递一次；不能只出现下划线或改动未选草稿。
