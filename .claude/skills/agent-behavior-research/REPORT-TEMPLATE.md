# 研究报告骨架：结果与重要等级在前

适用于数据研究、任务评价和长流程审计；按模式裁剪，不要求每个模式填满所有章节。这是
阅读顺序，不是研究执行顺序。所有发现步骤、验证记录与交付清单必须在结果及行动建议之后。
未测量项填“不可用”及原因，不填零。

## 1. 结果摘要

用 1–3 条直接回答：最重要的问题是什么、影响什么、建议先做什么。不以研究范围、工具使用、
测试通过或文件路径开场。

## 2. 按重要等级排列的发现

等级定义见 SKILL.md“报告与交付”。P0 / P1 / P2 表达重要性，`observed` / `candidate` /
`unverified` 表达证据状态，两者分开标注；没有 P0 就不设 P0 章节。任务评价不把五维标签
合成总分，数据研究不把工具指标写成任务质量结论。

每项使用以下结构，不按发现时间排序：

### [P1] 直接表达问题的标题 · [observed / candidate / unverified] · [稳定 ID]

1. **结果**：一句话判断，附最关键的观测值与分母；无法量化则说明。
2. **影响与定级理由**：为什么值得优先处理，影响的对象和边界是什么。
3. **建议行动**：修复还是先验证，什么可观察结果才算改进。
4. **必要限定**：影响该项解释的未知、反例或范围限制紧跟结论；不能只藏在附录。完整证据
   用稳定 ID 关联后文，不在这里展开取证流水账。

任务评价模式在每项中保留唯一 case ID、任务边界和五维证据摘要；长流程模式保留模式识别
证据、目标修订/恢复点和观察截止。数据研究模式保留指标分子/分母与来源范围。

## 3. 建议行动顺序

以有序列表说明先做什么、后做什么及原因。区分研究方法改进与产品修复，不把未获授权的修复
写成已实施；避免重复整段发现。

---

以下为后置复核材料，不能插到结果之间。

## 附录 A. 发现过程、来源与口径

- 来源、读取方式、运行时间、schema/解析器/规则版本；原始路径仅按需本机保留。
- 快照或指纹及覆盖对象；过滤条件、时区、半开边界和时间字段。
- 总体、单位、指标分子/分母、阈值、去重/配对身份、未知状态和排除依据。
- 抽样候选集、选择方法、seed、实际阅读量、唯一会话数及跨标签重叠。
- 解析失败、缺失、冲突、孤立记录、继承/双写和来源污染；对账差额与敏感性比较。
- 每项发现的完整源 ID、安全摘要、上下文范围、反例及撤回记录；不保存无关原始对话或工具
  参数全文。

按模式补充，不要求其他模式填写：

- **任务评价**：任务契约与请求锚点、观察截止、取样政策、包 hash、reviewer 身份与覆盖、
  五维标签及证据、缺评/单评/边界分歧、用户校验状态。
- **长流程审计**：模式识别证据与版本可知性、逻辑阶段/物理尝试、恢复链、派发回收、缺口
  与补读记录，以及相对顺利的对照。
- **数据研究**：Agent 失败模式研究涉及的层识别证据、覆盖/缺层和顺利对照；目标修订、压缩/
  交接、派发回收与验收转折点走查。

## 附录 B. 验证、复现与局限

- 可重复命令、机器产物、实际退出状态、有效用例或样本数量。
- 区分计算正确性、案例复核、代码验证、实际行为变化与因果效果，不以单项通过代替全部
  验证。
- 逐条核验报告与队列引用的存在、所属来源和语义支持；说明未验证项及缺失观测。
- 比较时列出两侧样本量、分母、缺失能力与不可比项；方法变化须重新生成受影响产物。
- 任务评价另列机械校验、独立评审、协调裁决和重新核验的结果；合成场景不能当生产准确率。

## 附录 C. 交付与机器可读改进队列

最后列可读报告、机器产物和复现脚本的位置。机器队列的等级与正文保持一致，不另造统计事实：

```json
{
  "id": "stable-finding-id",
  "priority": "P1",
  "priorityReason": "影响正确性或关键决策，需优先处理",
  "status": "candidate",
  "problem": "触发条件与可观察影响",
  "metricsRef": "本次产物中的指标及分母位置",
  "evidence": [{"source": "来源身份", "threadId": "完整标识", "messageId": "完整标识"}],
  "counterEvidence": [],
  "limitations": ["尚缺哪些证据"],
  "entryPoints": ["当前代码、配置或流程入口"],
  "nextVerification": "能证实或推翻候选的检查",
  "successCriterion": "什么可观察结果才算改进"
}
```

任务评价的评审 JSON 按现行 `TaskReviewInput` 和 TASK-EVALUATION 另行保存；本队列只承载
研究发现与改进候选，不替代评审记录，也不把五维标签合成 priority。
