# 后台任务生命周期

按 [总目录](README.md) 的编号执行。除特别说明外，等待期间不再提交用户输入，以验证任务自身的续跑责任。

1. **P0-38 后台投递暂时失败后自行结算**（[issue](../../../spec/issues/2026-10-09-subagent-callback-chain-audit.md)）
   1. 启动后台子任务，让首次父队列接纳暂时失败，随后恢复接纳。
   2. 不发新 prompt、不退出进程，等待原任务结算和父任务回应。
   3. 核对稳定 delivery ID 只投递一次；失败期间保留结果，不重跑子工具，恢复后自动完成。
2. **P0-39 预算边界仍消费后台结果**（[issue](../../../spec/issues/2026-10-08-background-result-consumed-before-budget-check.md)）
   1. 让父任务接近语义迭代或推理预算边界，同时完成后台子任务。
   2. 等待父 loop 的退出复查或自动续跑，不再发送用户输入。
   3. 核对后台结果只进入一次后续模型请求，并有父回复；预算边界不应吞掉投递资格。
3. **P0-40 取消后台子任务仍交付终态**（[issue](../../../spec/issues/2026-10-09-subagent-callback-chain-audit.md)）
   1. 启动后台 Agent，确认父会话能看到运行条目后取消该子任务。
   2. 等待 child 退出、父任务收到取消结果，再查看任务详情。
   3. 核对原 task ID 只结算一次，卡片不永久运行；父任务不因取消回调丢失而等待新输入。
4. **P0-74 取消后台任务确实停止且失败不伪装**
   1. 启动一个记录自身 PID 后长时间等待的后台 shell 任务与一个后台 subagent，在运行中通过界面既有取消路径取消所选任务并等待结算。
   2. 核对屏幕：被取消的条目进入取消终态而非继续运行，操作作用于所选任务，面板给出的操作提示与实际动作一致（不得把取消伪装成打开）；随后对已终态或不存在的任务再次取消，核对错误可见、不静默显示成功。
   3. 核对 `session/cancel-bg-task` 请求的 taskId、响应与终态事件：被取消的 shell 进程真实退出（用记录的 PID 复核），原 task ID 只结算一次，不产生第二个终态或复活。
5. **P0-75 中断或失败的现场保留可核对**
   1. 让一个后台 subagent 完成若干次工具调用并输出部分正文后中断，再让同类任务执行一段后失败。
   2. 核对屏幕：两种终态下详情仍保留中断前已产生的工具行与输出，并标注终态与原因；不因终态清空、不重写成成功；任务行给出终态符号与冻结耗时。
   3. 核对事件与持久数据：屏幕保留的记录与已送达事件及持久化内容一致，重开详情和在同一会话重载后现场仍在；不得伪造未收到的完成步骤、进度百分比或工作区改动摘要。
6. **P0-76 会话重载后任务状态如实呈现**
   1. 在会话 A 保留一个运行中的后台 subagent，并让另一个后台任务在退出前已结束；切到会话 B 后返回 A，随后退出进程重新加载 A。
   2. 核对屏幕：返回与重载后 A 的任务栏与 Tasks 面板只呈现在快照中确证的事实——已终态任务显示终态及其已收到的输出；缺少当前执行证据的非终态任务显示为未观测，不得冒充正在运行或正在推进，也不出现伪造的实时工具行。
   3. 核对 `session/bg-tasks` 快照请求与 revision 水位：缺口按快照重取，终态不被降级为运行中；重载不重跑旧工具、不复活旧执行，重启后的迟到结果不重启已关闭或已切换的会话。

## P1 补充场景

1. **P1-03 执行失败后新错误通知仍能激活**（[issue](../../../spec/issues/2026-10-08-async-error-notification-activation.md)）
   1. 让父模型请求失败，再让后台任务产生新的 Required 错误通知。
   2. 不发用户输入，观察父会话是否因新通知重新进入处理。
   3. 核对新错误被消费一次；旧失败请求不自旋重试，主动 Stop 后不自动激活。
