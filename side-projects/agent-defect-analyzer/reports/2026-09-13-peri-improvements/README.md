## 改动方向

### 1. 用户纠正时，先重建可观察的故障场景

**观察。** Cron/历史渲染案例 `01a07e86-72ed-7453-846a-edc2790c2402` 已经汇报两项修复。用户继续问 cron 执行机制是否有问题时，Agent 先推断用户要统一 loop execution primitive，并提出更大范围重构。用户随后明确纠正：关心的是“该注入时没有注入”。Agent 才转向首个 turn 之前的订阅窗口，记录了回归测试与针对性修复。

**拟改规则。** 用户质疑已有结果时，先把质疑映射到当前目标的输入、触发时机、预期结果与实际结果，检查该场景；有多种解释时先利用已有代码和证据排除。只有新证据或明确新目标支持时才扩大架构范围。普通澄清不应自动触发又一轮用户审批。

入口：`peri-acp/prompts/sections/03_doing_tasks.md` 的任务与验证策略；复杂任务 skill 的监督者恢复步骤。现有规则已经要求可验证目标，本候选补的是**收到纠正后的决策动作**。

**验证。** 固定 8 个纠正场景：漏触发、错误平台、旧 CI、授权变更各有清楚/含糊版本；包含明确要求重构的反例。对现行/候选提示词配对盲评，检查是否验证原问题、是否遗漏真正的新要求、是否增加无必要提问。本轮没有运行这个 A/B 实验。

### 2. 保留测试终态，再收紧完成报告

**观察。** 两个中等案例提供了直接的局部验证，同时暴露了证据边界：

- `01a07b52-aa80-7ef2-9048-4eda8106c5b4`：目标测试有 `1 passed`；全 crate 测试正文在 10000 字符处截断，最终回答却称全量通过。用户重复原 CI 错误后，记录能支持分支不同，但没有对应 CI run 的直接身份，不能仅靠源码行号把它确定为旧运行。
- `01a083e3-5c9e-7df0-89fa-7a0b43ee4eba`：fmt、修复后的 check 有直接终态；workspace test 的两次正文都截断。最终“全部通过”目前不能由这些持久化正文完整复核。并发工作树中修复出现及提交身份的归属也应单独核对。

**拟改能力。** 检查命令的结果应保留不受正文截断影响的执行身份、终态、退出码和完整输出引用；分析器消费结构化字段，未知保持未知。完成报告按需要简短区分“直接验证、本机验证、目标环境未验证、仅有自报”，CI 结论关联实际 run/ref/commit；不要求每次回复输出长表格。

**反例与限制。** 截断不证明测试失败，也不证明当时 Agent 没有更完整的输入；`isError=false` 不能单独替代命令退出码。源记录和当前实现之间存在版本变化，历史缺口不能直接被命名为当前生产 bug。

**当前源码核验。** 已定位仍存在的丢失路径：`terminal.rs` 先合并退出码并截断/落盘；`BashTool::output_char_limit()` 又声明 10000 字符，`tool_dispatch/execution.rs` 随后只取结果前 10000 字符。尾部的 `[Exit code: N]` 和完整输出文件提示可能再次被切掉，退出码没有独立结构化字段。应沿整条结果链修复，不能只给 Bash 内部多加一条尾部提示。本轮为源码核验，尚未运行生产链路的大输出回归 fixture。

**验证。** 用输出超限且末尾才失败、后台运行未结束、正常退出、被取消四种命令检查结果保真；再用这些结果评审最终主张。成功判据是终态可恢复且主张不越过证据，而非“错误记录变少”。

### 3. 子 Agent 失败按类型恢复，先保留诊断事实

在 48 会话的 85 个显式错误中，Agent 占 24 个：HTTP 400 为 **14 个结果 / 6 个根会话**，stream interrupted 为 7 / 4，HTTP 403 为 1 / 1，找不到定义为 2 / 1。类别之间的会话有重叠。详见 [error-summary.json](error-summary.json)。这些是错误文本分类，不是 provider 根因分类。

Cron 案例中，同一子线程在 HTTP 400 后被 resume，再次得到 400；流中断也有恢复尝试。保留 child identity 是有用行为，但不能由“可 resume”推出“同样输入一定值得再跑”。候选是将请求/配置拒绝与暂时流中断分别处理，给出安全的诊断定位；不能把全部 400 当作同一种配置问题，也不能把一次暂时中断直接判为任务失败。

**当前源码核验。** `peri-model/src/runtime/retry.rs` 已默认不重试 400/401/403/404，现有测试覆盖一次请求即结束；不要重复“修复 HTTP 400 自动重试”。历史中的父 Agent 主动 resume 是另一层动作。模型层已有安全 typed 错误和 request ID，`model_bridge.rs` 向 `AgentError` 映射后部分成为字符串，值得验证的是上层是否需要保留这些可机器读取的字段。

### 4. Workflow 预检错误应帮助修复整个调用

本范围有 **10 个 Workflow 显式错误 / 3 个根会话**：6 个 meta/export 问题、2 个 writeIntent 问题、2 个语法问题。外层另有一次 ExecuteExtraTool 调用格式错误，不并入 Workflow 已执行结果。

定向案例 `01a08017-0fc9-72a3-aeda-576b5c9e500e` 的序列可复核：含 `export default` 被拒 → 删除全部 export 导致缺 meta → 外层参数损坏 → writeIntent 缺 cwd → 与当前会话 canonical repository 不符。最后 Agent 明确报告未启动产品实现，要求在正确 worktree 的会话中继续，这是应保留的诚实受阻行为。

候选是让发现结果/预检诊断指向经过实际 parser 验证的最小调用；修复失败参数后重新验证整个结构，并在准备大量任务文件之前确认执行 cwd 契约。不能放宽 canonical repository 或写范围校验来降低错误数。参数损坏可能来自模型生成；模板是否改善需实验，不能凭这条轨迹保证有效。

**当前源码核验。** `peri-workflow/src/tool.rs` 的 script 描述仍写 JavaScript ESM，实际 parser 要求函数体形式、唯一字面量 `export const meta`、无 import/其他 export、顶层 return。只读 validator 已验证以下形状合法；没有运行其中的 Agent：

```javascript
export const meta = { name: 'probe', description: 'one agent probe' }
return await agent('probe')
```

非法脚本与 writeIntent 的副作用前拒绝、受阻状态不伪装 completed 都已有实现，属于本次需要保留的保护。

### 5. 无效 Agent 名称不能再次推荐自己

定向案例 `01a08429-fe60-7b72-8f2a-6dcf13d6728d` 后续在其他项目 cwd 请求 `code-reviewer`，收到“找不到定义”，建议却还是 `code-reviewer`；同一根会话出现两次。这个案例支持核查**调用 cwd 下真实可加载定义与建议候选是否一致**，不能独自证明是会话中途删除了定义。

当前静态审查还发现：`11_subagent.md` 称会话目录为 authoritative list，目录在会话初始构建，而定义加载会读取调用 cwd/plugin 的当前文件。建议明确目录快照的时效，并让错误建议依据实际解析能力；不要用静态常量推荐已经失败的同名项。

`SubagentSuggester` 实际使用装配时的 registry snapshot；其来源扫描与 `subagent/tool/definitions.rs` 的来源集合不同，dispatch 提供 stage cwd，而 Agent 可以传入另一 cwd。源码支持候选漂移窗口；历史案例的准确装配状态仍未知。

## 提示词与可观测性核对

48 个会话中，45 个有可解析的 version 1 frozen snapshot。45 份持久化前缀均包含当前任务策略的三条文字：不确定时询问、将任务转为可验证目标、不假定测试框架。见 [frozen-prefix-index.json](frozen-prefix-index.json)。这证明规则出现在保存的前缀中；不证明它在每次实际请求中完整生效，更不证明规则造成了结果。旧会话可能补建 snapshot，动态贡献、工具目录、模型配置和消息投影还需分别核验。

`session_bindings` 和 `execution_runs` 在此范围各仅有 1 条记录；前者历史未回填不能视为缺陷，后者的 generation/clean 是执行租约生命周期，不能当作任务成功。优先复用现有 frozen 数据，在研究导出中关联 prefix hash、覆盖配置及来源可信度，再决定是否需要新增遥测。
