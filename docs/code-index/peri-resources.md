# peri-resources 代码索引

> 执行恢复剥离见 [active plan](../../spec/issues/2026-10-07-remove-execution-recovery-plan.md)；schema版本以 `sessions/canonical.rs::CURRENT_SCHEMA_VERSION` 为准。

## 架构速览

- 执行恢复：Work/control 数据端口、reducer 与六张账本表移除；新库不创建，升级到当前形状时按 `schema_cleanup::removal_plan` 删除。`sessions/canonical.rs` 定义保留业务表及删除清单；本地 `sqlite_store/schema.rs` 与远端 `remote/schema_upgrade.rs` 负责版本转换。
- 历史数据：snapshot/history、frozen/inherited、消息 flags/projection、普通关闭意图与 OAuth 保留；普通远端 operation ledger 不属于 Agent 恢复账本。迁移验收命令与结果见 active plan，不宣称网络/重启全套已通过。
- 工作区身份（当前形状 11）：`workspaces` 的 `(machine_id, path)` 是唯一归属键，`project_id`/`identity`/`discovery` 只描述该路径当前观测到的对象，不参与身份；`legacy_execution_registrations` 已删除，`session_bindings.workspace_id` 与 `threads.workspace_id` 一致。见 [active plan](../../spec/issues/2026-10-08-remove-legacy-execution-registrations-plan.md)。

- 时间入口：生产路径经 `peri-time` 读取 UTC 墙钟、单调时钟并执行 sleep/timeout。`src/sessions/remote/connection.rs` 保留远端请求超时的 `Exceeded` 分类；`src/sessions/resources/deployment.rs` 与 `resources.rs` 保留关闭结清超时分类；`src/sessions/sqlite_store/connection.rs` 用单调时钟限制 schema 开库锁等待。持久字段继续使用既有 RFC 3339 形状，`ThreadMeta` 的 Chrono 类型在本 crate 边界由 `SystemTime` 转换。

- 定位：外部系统数据访问通道（§0），以 context 形式提供给 Agent / Middleware / Controller
- 结构：`config`（配置文件）、`sessions`（共用规则及 SQLite/Turso adapter）、`workflow`（Native workflow 资源实现门面）、`context`（`Resources` 唯一实例化入口，`context/sqlite.rs` 只在 Native 编译）
- 稳定不变量：`ThreadStore` trait / `ThreadMeta` / `BaseMessage` / `MessageFlags` 事实源在 `peri-acp-types`（sessions/mod.rs 注释）；本 crate 只实现、不解释业务语义

### OAuth 凭证路由（实现完成）

- 契约类型归 `peri-acp-types/src/oauth_credentials.rs`，本地/远端 provider 已在 Resources 落地；凭证表以 `(principal_id, workspace_id, server_key)` 为键，旧机器级凭证在迁移事务中清理；生命周期适配见 `src/sessions/resources/oauth_credentials.rs`。验收见存储 v2 active issue。
- 已完成数据流：部署注入 Resources provider → `mcp-packages/credentials/src/{lib,server,client}.rs` 受信 bootstrap MCP `CustomRequest` → `peri-acp/src/host/assemble.rs` 注入 `credentialsClient` → OAuth pool；凭证通道独立于等待授权的 tool pool，避免授权依赖自身。bootstrap 集成与 middleware 定向回归通过；实际云端、真实 OAuth 网络授权及多实例 refresh 未验证，结果统一见 active assessment。
- 不引入私有数据库、HOME 路径、额外开库、文件锁、迁移、兼容层、旧 JSON 或文件 fallback；删除 `FileCredentialStore`，旧凭证不导入，用户重新授权。持久 MCP 响应缓存按 Workspace ID 隔离；插件持久化与日志不在此凭证通道内。
- 默认逻辑 scope 为 principal `local` + Workspace ID；server key 绑定 endpoint/授权配置，动态连接还须绑定 incarnation。Workspace ID 从受信 Session 归属取得，同一 Workspace 的 thread 共享授权，异 Workspace 隔离。

## 跨模块契约

- 普通历史 rewind/remove 的 SQLite 实现在 `src/sessions/sqlite_store/session_data/history.rs`，由 `session_data.rs` 消费；远端测试装配位于 `src/sessions/remote/session_data_fixture.rs`，不属于执行恢复账本。

- Session ID/environment 现行契约见 [ARC-WORKSPACE-001](../standards/architecture-contracts.md) 与[现行设计](../design/session-id-environment.md)：机器身份发布与权限限制、迁移来源假设、恢复/执行边界和并发保证以此为准；跨实例执行协调归部署方，Peri 不提供旧执行接管；工作区身份、目录与 binding 校验不构成 Peri 内部执行所有权协议。

- 消费方：`peri-tui/src/app/mod.rs:88` 与 `peri-tui/src/cli_print.rs:136`（`Resources::open_with`，默认或显式路径失败均直接传播）；`peri-controller/src/controller.rs:222`（`Resources::open()` 后调用）；`peri-middlewares/src/`（plugin/loader.rs:14、assembly.rs）
- 契约类型：`ThreadStore` trait / `ThreadMeta` / `BaseMessage` / `MessageFlags` 事实源在 `peri-acp-types/src/store/mod.rs`（sessions/mod.rs 明确「接口契约归 peri-acp-types」）
- 门面依赖：Cargo.toml 仅保留 `peri-workflow` 等实际 Resources 实现
