# 功能登记与验收追踪

> 状态：登记规则现行；L1–L5 的语义及本次逐项评级为 #446 的可审查提案。
> 已检索当前仓库、#446、peri-e2e #10 及维护群五级/L1 记录，未取得旧 159 项草表或等级定义；不得将下表伪称历史裁决。维护者取得旧裁决后须对账，若冲突在同一变更修订评级及验收映射。

### FEATURE-LEVEL-001

- **Scope**：Peri 独立用户能力、SDK/宿主能力及其长期边界。
- **Rule**：功能重要度仅用 L1–L5，待评级为 U；与实现状态、问题 P 优先级、#443 阶段编号及 E2E 执行档位分开。以下为本变更提议并应用的定义，不作为已经核实的历史决定。
- **Verify**：审查评级理由是否符合能力缺失的用户影响；核心能力不得留空或用 U 逃避评级。

| 等级 | 本次提议定义 | 评级判据 |
| --- | --- | --- |
| L1 | 基础正确性与可信执行 | 缺失会阻断主任务，或破坏身份、权限、持久结果的基础保证 |
| L2 | 主要任务闭环 | 常用执行、会话、恢复、委派与控制路径的完整行为 |
| L3 | 扩展与专门入口 | 插件、工作流、部署适配及管理功能的独立用户价值 |
| L4 | 体验与效率 | 交互、性能、可维护消费等支持性能力，有可观察验收边界 |
| L5 | 局部展示细节 | 不改变任务结果、权限、身份及终态的样式或文案细节 |
| U | 尚未评级 | 必须写明裁决缺口，不得用作第六级 |

### FEATURE-REGISTER-001

- **Scope**：功能目录和能力变更。
- **Rule**：[功能目录](../reference/feature-catalog.md) 只登记稳定 ID、等级、功能与边界、唯一权威契约链接；每项一行，可见文字不超过 100 字。ID 永不复用；拆分、合并和退役须留下旧 ID 去向，不冻结旧表数量。不复制运行时 owner、开关或装配逻辑。
- **Verify**：运行 `python3 scripts/check-feature-catalog.py`；检查同一变更同步受影响契约及验收映射。

### FEATURE-EVIDENCE-001

- **Scope**：功能验收与发布声明。
- **Rule**：[验收映射](../verification/feature-acceptance.md) 逐项区分实现、目标、验证和阻塞。L1–L4 必须有可定位证据或具体缺口；源码/测试文件存在不等于验收通过。外置 E2E 的场景、断言、fixture 和编排由 peri-e2e #10 维护；L5 不因登记被强制新增 E2E。
- **Verify**：检查执行证据包含产品/测试版本、命令、结果和限制；未运行的写未复验，blocked 不计入 passed。
