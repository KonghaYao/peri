# 复制通道与远程剪贴板

按 [总目录](README.md) 的编号执行。复制写到**哪台机器**的剪贴板取决于 peri 进程与用户终端的相对位置：本机有显示环境写系统剪贴板，SSH、herdr 或无显示环境经终端 OSC 52 交给客户端终端。每步都要在 TUI 之外读取剪贴板核对内容，状态栏提示不能作为唯一证据。

1. **P0-77 本机复制写入系统剪贴板**
   1. 在本机（无 SSH 环境）启动 TUI，依次触发三种复制：消息区拖选含中文、emoji 与换行的文本；错误块的复制按钮；OAuth 弹窗的链接复制。
   2. 每次在 TUI 外用 `pbpaste`（macOS）、`wl-paste` 或 `xclip -o -selection clipboard` 读取剪贴板；再以 `PERI_CLIPBOARD=osc52` 启动重复一次。
   3. 核对剪贴板与来源文本逐字一致（不含视觉行号、渲染前缀与省略符），状态栏显示复制字符数；`PERI_CLIPBOARD=osc52` 时内容改由客户端终端接收、系统剪贴板保持不变。
2. **P0-78 SSH 会话复制经 OSC 52 到达客户端剪贴板**
   1. 用支持 OSC 52 且允许剪贴板写入的客户端终端（iTerm2、WezTerm、kitty、Ghostty、Windows Terminal、VS Code 终端等）SSH 登录无显示环境的服务器，在服务器上启动 TUI。
   2. 复制一段含中文与 emoji 的文本，随后在**客户端**读取剪贴板；服务器端不应被当作写入目标。
   3. 核对客户端剪贴板内容与选中文本一致，且 `~/.peri/logs/agent-tui.*.log` 没有剪贴板写入失败记录；客户端终端禁用 OSC 52（如 Apple Terminal）时内容到不了客户端剪贴板，须如实记录为终端能力缺失而非复制成功。
3. **P0-79 tmux 与显式通道覆盖**
   1. 在 tmux 内启动 TUI 并复制，分别在 `set -g set-clipboard on`（客户端终端 terminfo 需含 `Ms`）与 `set -g allow-passthrough on` 两种配置下重复——两者覆盖 tmux 的两条投递路径。
   2. 再以 `PERI_CLIPBOARD=native`（强制系统剪贴板）和 `PERI_CLIPBOARD=osc52`（强制终端通道）各重复一次；其中 `PERI_CLIPBOARD=native` 在 SSH 且服务端无显示环境时应回落终端通道。
   3. 核对已开启上述任一 tmux 配置时客户端剪贴板能拿到内容；回落发生时日志出现"剪贴板主通道写入失败，已回落备用通道"；两条通道都失败时日志保留两条失败原因；两种 tmux 配置都关闭时内容到不了客户端剪贴板（终端无确认响应，界面仍显示已复制字符数），须如实记录。
4. **P0-80 远程 Ctrl+V 粘贴引导**
   1. 在客户端剪贴板准备一段可识别文本，然后在 SSH（或 herdr、无显示容器）会话内按 Ctrl+V。
   2. 观察通知与输入区：服务端无显示环境时读不到剪贴板，须提示改用终端原生粘贴，且不插入任何内容、不静默吞掉按键。
   3. 改用客户端终端原生粘贴（Cmd+V / Ctrl+Shift+V，走 bracketed paste）重复一次，核对内容完整进入输入区；本机（非 SSH）Ctrl+V 读不到内容时保持既有静默，不出现该提示。
